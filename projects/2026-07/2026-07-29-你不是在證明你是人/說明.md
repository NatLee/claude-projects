# 你不是在證明你是人 —— 那十秒鐘，你在替一百年前的報紙打字

## 這頁的故事線

**鉤子**：一個你做過幾千次的動作。「請輸入下面看到的兩個字。」十秒鐘，你從來不會多想。這一頁只想請你再做三次。

**鋪陳**：三道驗證碼，跟你平常做的一模一樣。你填、你過關、你花了不到一分鐘。第三題我請你**故意亂打右邊那個字**——你還是過了。

**轉折**：你打了六個字，只有三個被檢查。左邊那個是系統早就知道答案的控制字，唯一任務是確認你是人；右邊那個是從老報紙掃描下來、**OCR 讀不出來**的字——系統不知道答案，所以你打什麼它都放行。你剛剛交出去的三個字，會攤成三張泛黃的剪報給你看。

**高潮（由使用者親手觸發）**：那亂打的人怎麼辦？按下「開票」。你第三題那個亂打的答案，和九個陌生人的答案排在一起，一張一張翻面——七票說它是 `quarantine`，你那一票被劃掉丟掉。一個人亂打不會怎樣，一個人認真打，就替所有人省下一秒。

**記憶點**：把鏡頭拉遠。四萬個網站、四億四千萬個字、一年之內讀完《紐約時報》一百三十年的檔案。然後回到現在——你已經很久沒打過那兩個字了，取而代之的是「我不是機器人」的方框，它看的是你的滑鼠怎麼移過來、在哪裡停了多久。收尾：**它從來沒有停止跟你要東西，只是你一直不知道自己付了什麼。**

**敘事容器**：一個可以真的操作的假驗證碼介面 ＋ 逐步揭曉。互動是「打字」，跟同批其他頁的點擊、拉桿都不一樣。

---

## 這是什麼

**reCAPTCHA**（2007 年上線，卡內基美隆大學 Luis von Ahn 團隊）把一個防機器人的機制，同時變成一台人力 OCR：

- 每題兩個字。**控制字（control word）**系統知道答案，用來驗證你是人。
- **未知字（unknown word）**來自書報掃描檔中 OCR 引擎讀不出來的區塊，系統不知道答案。
- 只要控制字打對，系統就假設你連未知字也讀對了，直接放行。
- 同一個未知字會發給多位使用者，答案彙整後取共識；有共識之後，這個字可以升格成新的控制字，用來抓那些總是亂打的機器人。

2008 年這套設計發表在《Science》上，論文標題是〈reCAPTCHA: Human-Based Character Recognition via Web Security Measures〉。

## 怎麼玩

1. 第一屏按「好，來吧」，做完三題。**第三題請照頁面指示故意亂打右邊那個字**——這是整頁的關鍵實驗。
2. 第二章看你交出去的三個未知字與出處。
3. 第三章按「開票」，看你亂打的那一票被十票的共識淘汰掉。
4. 第四、五章是規模與現在。

## 哪些是史實、哪些是示意重建

- **史實**：兩字設計（控制字＋未知字）、控制字通過即放行、多人共識、有共識後升格為控制字、上述所有數字、2009 年 Google 收購、後來從「打字」轉向行為訊號（v2 的「我不是機器人」核取方塊，以及 v3 的無介面評分）。
- **示意重建**：三題的具體字詞（`morning`／`wharves`、`harbour`／`telegraph`、`signal`／`quarantine`）與剪報上的年月。真實語料確實來自《紐約時報》1851 年以後的檔案，但這些字與日期的對應是為了說故事編的，頁面上每張剪報都標了「（示意）」。
- **示意重建**：票箱裡那九位「陌生人」的答案是預先寫好的（各含 1～3 個 OCR 常見誤讀，例如 `wharyes`、`telegroph`、`quarantlne`），這樣共識機制才看得出戲。真實系統的投票數與門檻並非固定十票。

## 模擬的簡化

- 頁面上的「未知字」其實是用 SVG 濾鏡（`feTurbulence` ＋ `feDisplacementMap`）把可讀的文字扭曲出來的，不是真的掃描檔。真實 reCAPTCHA 的未知字是原始掃描像素，本來就沒有「正確答案」的電子檔。
- 控制字比對做了正規化（去空白、轉小寫、丟掉標點），真實系統的容錯規則更寬鬆（例如允許一個字母的編輯距離）。
- 共識用單純的眾數，平手時取字母序較小者以確保結果可重現。真實系統會加權（考慮使用者過去的表現）。頁面上的第六組斷言刻意驗證了這個機制的極限：如果十個人裡有九個亂打成同一個字，共識就會錯——這是眾包本來就有的弱點。

## 技術

- 純靜態、自包含，`file://` 雙擊可開；無外連資源、無 fetch、無 ES module、無 canvas。
- SVG 只用來做文字扭曲濾鏡，沒有用到漸層描邊（避開 `stroke:url(#…)` 需要 `gradientUnits="userSpaceOnUse"` 的地雷）；濾鏡區域設為 `x="-20%" y="-40%" width="140%" height="180%"`，位移後不會被裁掉。
- `logic.js` 放純函式（正規化、控制字比對、共識票箱、題目資料），瀏覽器與 node 共用，以 node 斷言驗證 6 組性質。
- 進場與逐項浮現用 `setTimeout` 一次性排程與 `IntersectionObserver`，沒有綁 scroll，也沒有常駐 rAF。
- `[hidden]{display:none !important}`：避免 `.nextrow{display:flex}` 蓋掉 `hidden` 屬性導致按鈕提早出現。
- `prefers-reduced-motion` 完整降級（含 matchMedia change 監聽）：所有逐項延遲改為同時顯示。
- 無障礙：輸入框有 `aria-label`，扭曲字的 `<svg>` 有 `role="img"` 與 `aria-label`（螢幕閱讀器使用者可以直接讀到答案——這是刻意的，真實驗證碼的無障礙問題是另一個故事）；`aria-live` 播報每次驗證結果與開票結果；Enter 可送出。
- **沒有使用 localStorage**。
