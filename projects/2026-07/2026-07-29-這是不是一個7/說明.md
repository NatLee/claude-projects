# 這是不是一個 7？—— 規則寫不完的那一天

## 這頁的故事線

**鉤子**：螢幕上一個手寫的 7。「這是不是一個 7？」你花了 0.2 秒。現在難的來了——把你剛才怎麼知道的，寫成規則。

**鋪陳**：一張規則台。十六個樣本、六條你看得懂的判斷，每條可以要求「要有／不能有／不管」。分數即時更新，目標是十六個全對。你會很快衝到十二、十三分，然後開始鬼打牆：每救回一個樣本，就弄壞另一個。

**轉折**：729 種組合我全部替你跑過了，最高 13 分。不是你不會寫——因為在這六條規則眼裡，**課本上的 7 和一個大寫 T 一模一樣**（特徵向量都是 `1 0 0 0 0 0`）。而你的眼睛零點一秒就分得開，還說不出你是怎麼分的。

**高潮（由使用者親手觸發）**：按下「開始給它看」。一台只看得到 256 個格子黑白的感知器，被一個一個餵樣本。猜錯就把用到的格子往正確方向挪一點、猜對就什麼都不做。你看著它的「腦內圖」從全空白長出藍紅相間的一團，錯誤數一輪輪掉下來，第四輪十六題全對——而它從頭到尾沒拿到任何一條規則。

**記憶點**：那張腦內圖很醜，而且沒辦法被唸出來。它不是一句話，是 256 個數字。收尾回扣開頭：你還是零點二秒就知道那是 7，而且你到現在還是說不出你是怎麼知道的——**寫不出來，不代表你不知道**。整個機器學習都是從承認這件事開始的。

**敘事容器**：一張可以動手的「規則台」（假的規則編輯器）＋ 一台看得見在學習的機器。分章由按鈕推進。

---

## 這是什麼

OCR（光學文字辨識）從 1929 年的模板比對開始，走了半個世紀的「寫規則」路線：數封閉的圈、找筆畫端點、量傾斜角度。這條路在 1980 年代末走到盡頭——不是因為工程師不夠聰明，而是因為**手寫與印刷的變異，本質上寫不進有限條規則裡**。這一頁讓你親手撞上那面牆，再親眼看它被繞過去。

## 怎麼玩

1. 第一屏按「好，我來寫寫看」。
2. **規則台**：左邊六條規則各自選「要有／不能有／不管」，右邊十六個樣本即時被判定，綠色是判對、紅色是判錯。試著衝到 16 分（你不會成功）。到 13 分或按下「直接看答案」就會解鎖下一章。
3. **窮舉**：看 729 種組合的最高分，以及那對「規則分不開、眼睛一眼分得開」的雙胞胎。
4. **訓練**：按「開始給它看」，看感知器一個一個看樣本、犯錯、修正。可以按「從頭再來一次」換一個隨機順序重跑，收斂的輪數會不一樣。

## 十六個樣本

| 是 7 | 不是 7 |
|---|---|
| 課本上的 7、寫得很斜的 7、歐洲人的 7（帶橫槓）、起筆帶勾的 7、橫畫短一截的 7、寫彎了的 7、簽名時的 7（幾乎沒橫畫）、又粗又帶槓的 7 | 1（帶旗子與底座）、光禿禿的 1、2、9、4、大寫 T、5、一道斜線 |

樣本不是逐格手畫的點陣圖，而是用**筆畫**描述（線段與二次貝茲弧），再即時點陣化成 16×16。筆畫半徑就是「筆的粗細」，所以「又粗又帶槓的 7」真的比較粗。這樣做的好處是每個樣本的差異來自筆順與角度，而不是我一格一格塗出來的偏見。

## 六條規則怎麼算的

全部由點陣圖直接計算，沒有任何人工標註：

| 規則 | 判準 |
|---|---|
| 上面有一條橫畫 | 最上 28% 的列裡，最長的連續墨段 ≥ 45% 寬 |
| 中間有一條橫槓 | 中間 34%～70% 的列裡，最長連續墨段 ≥ 26% 寬 |
| 有封閉的圈 | 從邊界灌水（flood fill），灌不到的空白區 > 0 |
| 下面有一條橫線 | 最下 20% 的列裡，最長連續墨段 ≥ 40% 寬 |
| 主筆畫從右上斜到左下 | 上半墨跡質心 x − 下半質心 x ≥ 1.6 格 |
| 墨跡碰到最左邊 | 最左兩欄有墨 |

## 為什麼一定失敗

因為 `課本上的 7` 與 `大寫 T` 的六維特徵向量完全相同（`1 0 0 0 0 0`），但答案相反。只要存在這樣一對，**任何**只讀這六個特徵的規則系統都不可能全對——這是邏輯上的必然，不是調參數的問題。頁面上的 13/16 是窮舉 3⁶ = 729 種組合實測出來的上限。

## 那台學生是什麼

一個**感知器**（Rosenblatt, 1958），輸入是 256 個像素（0/1），輸出是「是不是 7」：

- 初始權重全部為 0。
- 每看一個樣本：算 `w·x + b`，大於 0 就說「是 7」。
- 答錯就把有墨的那些格子的權重往正確方向加減 `lr`，並更新偏置；答對什麼都不做。
- 一整輪都沒有再改，就停下來。

這十六個樣本在 256 維空間裡是線性可分的，所以感知器收斂定理保證它一定會停——實測 30 個不同的隨機順序全部在 120 輪內達到 16/16，通常 3～5 輪就結束。

注意這是**訓練集全對**，不是「學會了 7」。真正的 OCR 要的是對沒看過的字也對，那需要多得多的資料與更強的模型。這一頁想講的不是感知器多厲害，而是**方法論的轉向**：從「把知識寫進程式」變成「把例子餵進程式」。

## 歷史時間軸（頁面第四章）

| 年份 | 事件 |
|---|---|
| 1929 | Gustav Tauschek 取得「閱讀機」專利，用機械模板比對辨識字元 |
| 1950s | 規則式 OCR：封閉圈數、端點、筆畫方向；換字體就得重寫 |
| 1968 | OCR-B 字體問世（Adrian Frutiger 設計），人機都讀得懂，後來成為護照機讀區的標準字體 |
| 1976 | Kurzweil 閱讀機：第一台不挑字體、能把印刷品唸出來的機器 |
| 1989 | Yann LeCun 等人以卷積網路辨識美國郵政的手寫郵遞區號 |
| 2007 | reCAPTCHA 上線，把 OCR 讀不出的字交給人類，一年內讀完《紐約時報》百餘年檔案 |

## 技術

- 純靜態、自包含，`file://` 雙擊可開；無外連資源、無 fetch、無 ES module、無 canvas、無 SVG。
- 點陣圖用 CSS grid（`repeat(16, 1fr)` ＋ `aspect-ratio:1`）繪製，格子隨容器縮放，不會撐破面板。
- `logic.js` 放全部純函式（點陣化、特徵、規則引擎、窮舉、雙胞胎偵測、感知器），瀏覽器與 node 共用。
- 訓練動畫用 `setInterval` 每 150ms 餵一個樣本，`document.hidden` 時直接跳過不推進，分頁切回來不會一次補完。
- 進場動畫用 `IntersectionObserver`，沒有綁 scroll。
- `prefers-reduced-motion` 完整降級（含 matchMedia change 監聽）：訓練直接跑完呈現結果，逐句浮現改為直接顯示。
- 無障礙：規則的三態切換是原生 `button` ＋ `aria-pressed`，包在有 `aria-label` 的 `role="group"` 裡；`aria-live` 播報每次規則變更與訓練結果。
- **沒有使用 localStorage**。
