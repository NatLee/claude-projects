# 你最有把握的那段記憶

類別：奇聞軼事
主題：閃光燈記憶（flashbulb memory）其實會壞掉，而且你完全不會發現

---

## 一、故事線

### 鉤子｜不定義名詞，先讓你點頭

第一屏不解釋任何學術名詞。它直接切進一個幾乎每個人都有的經驗：

> 有些消息，你記得的不只是內容。你記得你人在哪裡、手上正在做什麼、是誰告訴你的、那個房間當時是什麼光線。畫面清晰得像一張照片。你從來沒有懷疑過它。

視覺上是一個檔案盒，卡片正從裡面冒出來——伏筆先埋著，還不說是什麼。

### 轉折一｜1986 年 1 月 29 日：有人替他們留了底稿

挑戰者號事故的隔天早上，一位心理學家在心理學導論課上發下一張油印問卷，只問一件事：你是怎麼知道這件事的。106 個學生在事發不到 24 小時內填完七個問題。

這一章的重點不是災難本身，而是那個當下有人做了一件很奇怪的事：**把一群人「剛聽到消息那一刻」的版本，白紙黑字凍結起來，收進盒子。** 這在記憶研究裡極為罕見——大多數時候，沒有人有底稿。

### 高潮｜兩年半後，由使用者親手把卡片抽出來

這是整頁的互動核心，也是「哇」的所在。

使用者按「從盒子裡抽出下一張」。抽出來的是 **1988 年那一份**——那個人現在記得的版本，寫得流暢、細節豐富，還附上他自己打的信心分數（1–5）。

然後頁面問使用者一個問題：**這一份，跟他 1986 年親手寫下的，對得上嗎？**

按下「對得上」或「對不上」之後，**1986 年的原卡才從盒子裡翻出來，壓在旁邊**。兩份並排，七題逐題標上「相符 / 不符」。落差自己說話，不需要旁白。

四張卡片刻意做成荒謬程度遞增：

| 卡片 | 七題相符 | 自評信心 | 那一張的感覺 |
|---|---|---|---|
| 受試者 A | 5 / 7 | 4 / 5 | 大致對得上，只有時間和結尾跑掉。看起來沒事。 |
| 受試者 B | 3 / 7 | 4 / 5 | 一半不到。地點、來源、身邊的人全換了。 |
| 受試者 C | 1 / 7 | 5 / 5 | 只剩「感覺」對得上。而他圈了最高信心。 |
| 受試者 D | 0 / 7 | 5 / 5 | 七題全錯。信心滿分。 |

第一張讓人鬆懈，最後一張收網。這個順序是刻意的。

### 轉折二｜數字：把信心和正確擺在一起

版面在這裡從溫暖的檔案室（牛皮紙、手寫感、油印格線）**切換成冷靜的資料視覺語言**（深藍灰、等寬字、格線）。這個色溫轉換本身就是敘事的一部分：故事講完了，現在看帳。

一張橫條圖，兩條長度換算成「佔各自量表滿分的比例」，所以 7 分制和 5 分制可以並排比較：

- 記得對的：**2.95 / 7 分**，約滿分的 42.1%
- 覺得自己記得對的：**4.17 / 5 分**，約滿分的 83.4%
- 中間用虛線標出那段 **41.3 個百分點** 的缺口

### 轉折三｜真正嚇人的地方

到這裡讀者大概會想：那總能分辨吧，記得越清楚的應該越準？

研究的答案是：鮮明度和信心之間確實有正相關（記得越鮮明的人越有把握），但**鮮明度和信心都預測不了記憶的一致性**。兩個指標互相呼應，卻誰也接不到真相那一端。

關係圖把這件事畫出來：鮮明度 ↔ 信心之間是一條實線（正相關），兩者往「一致性」的連線則被打叉。

### 記憶點｜回馬槍

結尾不寫「原來記憶不可靠，真有趣」。它回頭去打第一屏那段「你也有的」記憶：

> 你剛剛讀完的這一切，不會讓它變得模糊一點。它還在那裡，一樣清楚，一樣有把握，一樣不像是編的。
>
> 那才是這個研究真正的結論——不是記憶會壞，是壞掉的時候，儀表板不會亮任何一盞燈。
>
> 1986 年那個盒子的意義，在於有人替他們留了一份底稿。而你的那一張，沒有人抄過。

## 二、這是什麼

一個單頁的假文件式互動敘事。容器是**一疊 1986 年的手寫問卷卡，被從檔案盒裡一張一張抽出來**。整頁不使用任何照片或有版權圖像，檔案盒、卡片、紙張質感、油印問卷、圖表全部是 CSS 與 SVG 手工做的。

## 三、怎麼玩

1. 從第一屏往下捲，讀完 1986 年那一章。
2. 按「從盒子裡抽出下一張」，會出現一張 **1988 年**的問卷卡（那個人兩年半後記得的版本）與他的自評信心。
3. 先猜：「對得上」還是「對不上」。
4. 按下去之後，**1986 年的原卡**會翻出來壓在旁邊，七題逐題標記相符 / 不符，並給出正確題數。
5. 一共四張，一張比一張離譜。抽完之後才進入數字那一章。

進度會記在瀏覽器本機，下次回來可以從上次的位置繼續。

## 四、為什麼有趣

多數談記憶的內容停在「記憶不可靠」，這句話大家都知道，也因此沒有殺傷力。

這個研究的特別之處在於它有**底稿**。1986 年那 106 份問卷不是事後回想，是事發 24 小時內寫的。所以兩年半後的落差不是「大家記憶都不同」的模糊印象，而是一個可以逐題比對、可以打分數的硬證據。

而真正讓人背脊發涼的不是 2.95 分，是 4.17 分——**錯得最徹底的那些人，把信心圈到了最高。** 這代表你腦子裡沒有任何一個可以用來自我檢查的訊號。你不會有「這段記憶好像怪怪的」的感覺，因為那個感覺根本不存在。

互動的設計就是為了讓讀者親身經歷這件事：你會先幫受試者 A 說話（他寫得很像真的），然後看到受試者 D 七題全錯還滿分信心。你剛剛在他身上看到的，你在自己身上看不到。

## 五、完整資料來源

**Neisser, U., & Harsch, N. (1992).** *Phantom flashbulbs: False recollections of hearing the news about Challenger.* 收錄於 E. Winograd & U. Neisser (Eds.), *Affect and accuracy in recall: Studies of "flashbulb" memories* (pp. 9–31). Cambridge University Press.

本頁引用的事實，全部來自這一篇，且僅限以下這些：

| 事實 | 內容 |
|---|---|
| 事件日期 | 1986 年 1 月 29 日，挑戰者號在升空 73 秒後解體 |
| 第一次施測 | 事故隔天發下問卷，**106 位**心理學導論課學生在事發**不到 24 小時內**填答 |
| 問卷內容 | 寫下自己怎麼得知這個消息，並回答七個問題（人在哪、在做什麼、當時的情緒等） |
| 第二次施測 | **兩年半後**，**44 位**原受試者再答一次同一份問卷 |
| 追加項目 | 第二次額外請受試者**以 1 到 5 分為自己記憶的正確度打信心分數** |
| 主要結果 | 平均正確分數 **2.95（滿分 7）**；平均信心 **4.17（滿分 5）** |
| 關鍵發現 | 記憶的鮮明度與信心之間有正相關，但**鮮明度與信心都無法預測記憶的一致性** |

背景概念：「閃光燈記憶」指的是重大事件發生當下的情境細節，會像被閃光燈照下來一樣鮮明持久。這項研究挑戰了它。

## 六、「示意卡片不是原始逐字稿」的聲明

**這一點很重要，頁面上也用一句話講明了。**

互動區裡四位「受試者 A / B / C / D」的問卷卡片內容，是**依研究描述改寫的示意卡片**：

- **不是**原始逐字稿，**不是**論文附錄的引文，**不是**任何真實受試者寫下的文字。
- 「受試者 A / B / C / D」是虛構的編號，不對應論文中的任何個案。
- 卡片上的相符 / 不符題數、以及每張卡的自評信心分數，都是為了敘事而設定的示意值，**不是**論文報告的個案數據。

### 改寫原則

1. **只重現研究描述過的落差「型態」，不重現內容。** 例如「原本是別人口頭轉述，兩年半後變成親眼在電視上看到」這一類典型的來源置換，是這類研究普遍描述過的現象；具體的房間、時間、人物則是為了敘事而寫的。
2. **不杜撰任何數字。** 頁面上出現的所有統計數字（106、44、2.95、4.17、7 分制、1–5 信心）一律照原文，沒有任何一個是編的。示意卡片的個別分數則明確標示為示意。
3. **不冒充史料。** 卡片標頭寫著「示意卡片」，互動區下方有獨立的警語框，本文件此節再詳述一次。整頁沒有任何地方宣稱擁有原始資料。
4. **不涉及災難本身的描寫。** 卡片問的全部是「你如何得知這個消息」，不描寫傷亡細節。

### 語氣紀律

挑戰者號是七位太空人罹難的真實災難。本頁提到事件本身時保持克制與尊重：只在第一章用兩句話交代事實與罹難人數，之後全篇焦點都在「人們如何記得聽到消息的那一刻」，不獵奇、不拿災難本身開玩笑。

## 七、技術註記

### 檔案

| 檔案 | 內容 |
|---|---|
| `index.html` | 單一自包含頁面。內含全部 CSS 與頁面互動邏輯。 |
| `engine.js` | 純函式模組（`Flashbulb`）。問卷比對、座標換算、猜測判定與示意卡片資料。 |
| `說明.md` | 本文件。 |

### 純函式（`engine.js`）

以 IIFE 匯出全域 `Flashbulb`，結尾附 `module.exports`，**不是 ES module**，可直接 `<script src>` 載入，也可被 Node `require` 測試。

- `compareAnswers(a, b)` — 比對兩份答案鍵陣列，回傳 `{ total, correct, wrong, flags }`。非陣列、`null`、非字串元素、長度不一致都不會拋錯（長度不同時只比對重疊部分）。
- `answerKeys(subject, year)` / `scoreSubject(subject)` — 取出某年的答案鍵、直接算出一位受試者的落差。
- `normalizeScore(value, min, max)` — 夾在區間內再映射成 0–1，任何垃圾輸入都不回傳 `NaN`。
- `toChartX` / `accuracyToX`（0–7 分）/ `confidenceToX`（1–5 分）— 分數換算成圖表軸座標，兩端剛好落在軸的兩端，不出界。
- `barGeometry(value, max, x0, width)` — 條狀圖幾何（以佔滿分比例計算長度，讓 7 分制與 5 分制可以並排）。
- `gapPercent` / `chartSummary()` — 缺口百分點、以及圖表的文字版摘要。
- `judgeGuess(guess, result)` — 依使用者猜測給出判定。`guess` 非法、`result` 為 `null` 或含負數 / `NaN` 都會被吸收成安全值。

### 靜態與相容性

- 純靜態自包含，`file://` 雙擊即可開啟。沒有 `type="module"`、沒有 `fetch()`、沒有任何外部資源（連 CDN 都沒有）。
- **不使用 canvas。** 兩張圖表與所有插圖都是 SVG，質感靠 CSS 漸層與 repeating-gradient。
- **沒有任何照片或有版權圖像。** 檔案盒、卡片、油印問卷、紙張紋理全部是 CSS / SVG 自製。
- SVG 一律使用**純色描邊**，漸層只用在填色，避開 `stroke:url(#g)` 在水平／垂直線上不繪製的地雷。`drop-shadow` 沒有掛在零面積路徑上。
- 沒有使用 dasharray 描線動畫。

### 動畫與效能

- 所有動畫只用 `transform` 與 `opacity`。
- 圖表的長條增長動畫只在確認瀏覽器支援 `transform-box: fill-box` 時才啟用（`CSS.supports` 檢查），否則直接顯示完整長度，不會出現長條被錯誤縮放的情形。
- 進場動畫先讀一輪 `requestAnimationFrame` 再套用 class，避免 transition 被跳過。
- 若 `document.hidden`（背景分頁），圖表直接跳到終值而不播放動畫。
- 捲動進場一律使用 `IntersectionObserver`，**沒有綁 scroll 事件**。

### 防呆

`window.matchMedia`、`IntersectionObserver`、`requestAnimationFrame` 任一不存在都不會讓整頁掛掉：

- 沒有 `IntersectionObserver` → 加上 `no-io` class，所有內容直接顯示（不會永遠停在 opacity 0）。
- 沒有 `requestAnimationFrame` → 退回 `setTimeout`。
- 沒有 `matchMedia` → 視為不需要降級，整段包在 `try / catch` 裡。

### 無障礙

- 所有互動元件都是真的 `<button>`，可用鍵盤 Tab / Enter 操作，有 `:focus-visible` 外框。
- 抽卡結果區為 `role="status"` + `aria-live="polite"`，狀態變化會被螢幕閱讀器讀出。
- 兩張 SVG 圖表都有 `role="img"` 與完整的 `aria-label`，圖表下方另外提供**文字版摘要**（由 `chartSummary()` 產生，與圖上的數字同源）。
- **顏色不是唯一資訊**：逐題比對用「✓ 相符 / ✕ 不符」文字標籤加波浪底線；圖例用實心 / 斜線兩種紋理區分；每條長條旁邊都直接標出數值與百分比。
- 信心分數除了圓點，也同時以「4 / 5」文字呈現，並附 `aria-label`。
- `prefers-reduced-motion: reduce` 完整降級（進場、卡片翻出、長條增長、游標提示全部關閉），並用 `matchMedia(...).addEventListener('change', ...)` 追蹤即時切換（附 `addListener` 舊版退路）。

### 版面

- 手機 <560px 單欄可讀：卡片改為上下堆疊，檔案盒與按鈕改直排，SVG 內的字級與線寬同步放大回可讀範圍。

### localStorage

前綴 `flashbulb_`，共四類鍵：

- `flashbulb_drawn` — 已抽出的卡片張數
- `flashbulb_right` — 猜對次數
- `flashbulb_guess0` ~ `flashbulb_guess3` — 每張卡片按下的猜測（`match` / `drift`）

所有讀寫都包在 `try / catch` 裡。在部分瀏覽器以 `file://` 開啟時，`localStorage` 會因為 opaque origin 直接丟出 `SecurityError`——頁面會安靜地吞掉，功能完全不受影響，只是不記進度（jsdom 測試已驗證這條路徑產生 0 個 JS 錯誤）。還原時若讀到髒資料（非數字、負數、超出範圍），會被夾回合法區間，不會顯示 `NaN` 或超過總張數的計數。

### 測試

- `node --check engine.js` — 語法檢查通過。
- 純函式單元測試（`assert`）：21 組，涵蓋 7 / 0 / 部分相符、`null` 與非陣列輸入、長度不一致、非字串元素、座標換算兩端不出界、各種垃圾輸入不回傳 `NaN`、以及猜測判定的異常輸入。
- jsdom 冒煙測試：20 項。四張卡片全部抽過、兩種猜測都按過，驗證 **0 個 JS 執行錯誤**、畫面無 `NaN` / `Infinity` / `undefined`、逐題標記數量與計分一致、`localStorage` 前綴與還原正確、以及在缺少 `matchMedia` 與 `IntersectionObserver` 的環境下不掛掉。
