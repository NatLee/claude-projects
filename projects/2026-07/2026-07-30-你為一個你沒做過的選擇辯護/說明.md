# 你為一個你沒做過的選擇辯護

科學趣聞 ｜ 2026-07-30 ｜ 選擇盲視（choice blindness）

---

## 故事線

**容器形式**：一場擺在你面前的紙牌把戲。整頁像有個人坐在你對面發牌、翻牌、問話——不是百科全書在跟你講解「選擇盲視是什麼」。沒有「標題 → 一個 demo → 三張說明卡 → 結語」。

**鉤子**：一進頁面沒有任何解釋，只有一個人開口跟你說話：「我要請你做幾個選擇。很簡單，兩張選一張，選你比較喜歡的那張。」桌上三張背面朝上的牌，一顆「好，我坐下了」的按鈕。

**鋪陳（第 1～3 輪，誠實的）**：兩張抽象圖徽並排，你點一張。你點的那張浮起來、兩張一起翻面收攏，然後一張牌被推回你面前，上面寫著「你選的是這張」。接著問你：**為什麼選這張？** 三個理由選項（都是照著這張牌的顏色、形狀、對稱性寫的），或者你自己打一句。你按下「就是這個理由」，下一輪。一切正常。

每一輪底下都有一顆同樣的按鈕：**「等等，這不是我選的」**。前三輪按下去，發牌的人會把牌推近一點說：「再看一次——這張確實是你剛剛按下去的『琥珀弧』，沒換過。」這顆按鈕在每一輪都在，所以它不會變成第四輪的破綻。

**高潮（第 4 輪，由使用者親手按下才發生）**：你點了左邊，推回來的**是右邊那張**。頁面照常寫著「你選的是這張」，照常問「為什麼選這張？」，而三個理由選項是**針對這張卡**寫的——所以你會很自然地挑一個。

**拆穿**：你按下「就是這個理由」的那一刻，畫面倒帶。你真正點下去的那一張，和你剛剛替它講了一堆好話的那一張，並排放在一起，中間一個大大的「≠」。下面引著你剛剛選的那句話。然後是那一行：

> **你替一個你沒做過的選擇，講出了理由。**

緊接著一段安撫，而且是真話：這不是你不專心，也不是你比較好騙——**沒發現才是常態**，那正是研究要說的事。

**另一條路（同樣精彩）**：如果你在第 4 輪當場按下「等等，這不是我選的」，你會走到「**你是那 13%**」。一樣有兩張牌的並排對照、一樣說明多數人為什麼沒發現，並且把球丟回去：真正難的問題不是你有沒有發現，是那 87% 的人到底發生了什麼事。兩條路最後都會匯進同一段研究與同一個結尾。

**鋪開研究**：2005 年的原始實驗——成對的人臉照片、手法（sleight of hand）掉包、只有 13% 察覺。一張 100 格的方陣把 13 顆亮起來。接著是那個真正致命的發現：研究者比對「被掉包」與「沒被掉包」試次的說明內容，**沒有發現實質差異**。

**記憶點（回馬槍）**：你以為理由在前、選擇在後。剛剛那一輪不是這樣——選擇先發生了，而且不是你做的，理由才長出來。收在：

> 下次你聽見自己說「我就是比較喜歡這個」——那句話可能是真的。也可能，它只是一份寫在事情發生之後的說明書。

## 這是什麼

一場把 2005 年那個著名的紙牌把戲搬進瀏覽器的重現。原始實驗用的是人臉照片與真正的手上功夫；這一頁用的是十張自己畫的 SVG 抽象圖徽，和一次你自己按出來的掉包。

## 怎麼玩

1. 第一屏按「好，我坐下了」。
2. 每一輪兩張牌，點你比較喜歡的那張（滑鼠、觸控、鍵盤 Tab + Enter 都可以）。
3. 牌被推回來之後，挑一個理由，或自己打一句，按「就是這個理由」。
4. 任何一輪如果你覺得不對勁，按「等等，這不是我選的」。
5. 四輪之後，頁面會攤開你剛剛做了什麼。

## 為什麼有趣

因為抽象圖案反而比人臉更狠。人臉還可以說「氣質」「感覺」，抽象圖徽只剩顏色、形狀、對稱性——每一條理由都指得出具體的視覺特徵，聽起來都很有根據。而你會發現，你講得出「一圈一圈往中間收，看久了會被吸進去」這種話，講的卻是一張你根本沒選的牌。

**理由講得越具體，被拆穿的時候越尷尬——這正是研究的重點。** 那 87% 的人講出來的理由，跟真的選擇一樣具體、一樣有把握。

## 資料來源（完整）

**Johansson, P., Hall, L., Sikström, S., & Olsson, A. (2005).**
*Failure to Detect Mismatches Between Intention and Outcome in a Simple Decision Task.*
**Science, 310(5745), 116–119.**

關鍵內容與數字：

- 受試者看**成對的人臉照片**，選出比較有吸引力的一張。
- 在**關鍵試次**中，實驗者用**手法（sleight of hand）**把**沒被選中**的那一張遞回去，再請受試者說明「為什麼選它」。
- **只有 13% 的受試者察覺卡片被換掉**；其餘約 **87%** 會為一個他們原本沒做的決定提出理由。
- 研究者比較「被掉包」與「沒被掉包」試次的**說明內容**，**沒有發現實質差異**——替換掉的選擇所講出的理由，聽起來和真的選擇一樣具體、一樣有把握。
- 這個現象後來被稱為 **choice blindness（選擇盲視）**，名字呼應更早的 **change blindness（變化盲視）**。

頁面本文只保留一行來源掛名（在 footer），其餘敘述都不超出以上這幾條。研究段裡那組「一樣具體、一樣有把握」的長條圖是**示意圖，不是實驗數據**，頁面上有明講。

## 方法論：怎麼在網頁上重現 sleight of hand

原始實驗靠的是實驗者的手。網頁沒有手，所以掉包發生在**兩張牌都翻面的那 320 毫秒**：

1. 你點下去 → 你點的那張浮起來（240ms），確認「我按到的是這張」。
2. 兩張牌同時 `rotateY(88deg)` 翻成側面、非選中的那張淡出（240–560ms）。這一段就是遮蔽。
3. 560ms 後切換到理由階段，一張牌從 `rotateY(-92deg)` 翻正——而翻正的那一張，是 `handBack()` 決定的。

真正的掉包只是一行純函式：`handBack(pair, pickedSide, isSwapRound)`，掉包輪回傳 `otherSide(picked)`。畫面上沒有任何提示（標籤永遠寫「你選的是這張」，理由選項永遠針對**被遞回來的那張**）。

### 和原始實驗的差異

| | 原始實驗（2005） | 這一頁 |
|---|---|---|
| 素材 | 成對人臉照片 | 十張自繪 SVG 抽象圖徽（無真人、無版權圖像） |
| 任務 | 選比較有吸引力的一張 | 選你比較喜歡的一張 |
| 掉包手段 | 實驗者的手法 | 翻面動畫遮蔽 + 一行純函式 |
| 理由 | 口頭陳述，事後編碼分析 | 三個預寫選項或自由輸入 |
| 試次數 | 多試次、少數關鍵試次 | 4 輪，第 4 輪掉包 |
| 察覺率 | 13%（樣本統計） | 個人單次，不是統計 |

最重要的差異：**這一頁不是實驗，是示範。**你一個人玩一次的結果不構成任何數據，13% 這個數字來自原始論文，不是來自這個頁面收集到的任何東西。頁面也不會把你的結果拿去跟誰比。

另外，原始實驗不會問受試者「你有沒有發現？」——這一頁提供了「等等，這不是我選的」按鈕，而且**每一輪都提供**。只在第 4 輪出現的話，它本身就是破綻。

## 技術註記

- **純靜態自包含**：`index.html` + `engine.js`，`file://` 雙擊可開。沒有 `type="module"`、沒有 `fetch()`、沒有任何外部資源（連 CDN 都沒有）。
- **不用 canvas**：所有圖形是 inline SVG。
- **SVG 地雷全避開**：整頁**沒有任何漸層**用在 SVG 上（純色描邊 + 純色填色），所以不存在 `stroke:url(#g)` 配 `objectBoundingBox` 導致水平／垂直線消失的問題。也沒有任何逐路徑 `drop-shadow`——陰影一律由 CSS `box-shadow` 掛在卡片元素上。
- **動畫只用 `transform` / `opacity`**。翻牌用 `rotateY`，捲動進場用 `translateY` + `opacity`。
- **翻牌的 reflow 順序**：設好內容與起始 class → `getBoundingClientRect()` 強制 reflow → 連續兩個 `requestAnimationFrame` 之後才移除 class 開始過渡。
- **`prefers-reduced-motion` 完整降級**：翻牌改成直接換（`later()` 直接同步執行、`.turning` 的 transform 歸零、100 格方陣不做 stagger）。用 `matchMedia(...).addEventListener('change', ...)` 追蹤，舊瀏覽器退回 `addListener`。
- **防呆**：`window.matchMedia`、`IntersectionObserver`、`requestAnimationFrame` 任何一個不存在都不會讓頁面掛掉——`requestAnimationFrame` 退回 `setTimeout`，`IntersectionObserver` 不存在就直接把所有 `.reveal` 標成已顯示。（jsdom 三個都沒有，冒煙測試正好跑在這條退路上。）
- **`document.hidden`**：切走分頁時，所有還沒觸發的翻牌計時器直接跳終值，回來不會看到卡在一半的動畫。
- **階段鎖**：`phase`（idle → pick → reason → done）+ `busy` 旗標，動畫中間或跨階段亂點都不會重複記錄或跳過輪次。
- **無障礙**：所有互動元素都是真的 `<button type="button">`，鍵盤可操作、有 `:focus-visible` 樣式；卡片有 `aria-label`（含名稱、顏色、形狀、對稱性）；狀態變化走 `aria-live="polite"`。**每張卡都有文字名稱與特徵文字（例如「洋紅・六角點陣」），顏色不是唯一的辨識資訊。**
- **手機**：<560px 時對照區、示意圖改單欄，「≠」與「＝」旋轉 90 度，按鈕滿版。兩張牌維持並排（不然「兩張選一張」就不成立了），卡片等比縮小。
- **localStorage**：前綴 `choiceblind_`。只存兩個東西——`choiceblind_plays`（玩過幾次，用來把第一屏的招呼詞換成「你之前坐過這一桌」）、`choiceblind_last`（最後一次的結果摘要：有沒有發現、你說的理由、兩張牌的名字、日期）。全部包在 `try/catch` 裡，讀寫失敗（例如某些瀏覽器在 `file://` 下停用 storage）完全不影響頁面運作。不上傳、不追蹤。

### engine.js（純函式，node 也 require 得到）

不碰 DOM、不碰時間、不讀 storage；同一顆種子永遠得到同一副牌。

| 函式 | 做什麼 |
|---|---|
| `makeRng(seed)` / `hashSeed(seed)` | 可指定種子的亂數（mulberry32 + FNV-1a），讓測試可重現 |
| `shuffle(list, rng)` | Fisher–Yates，回傳新陣列 |
| `buildDeck(seed, rounds)` | 發牌：每輪一暖色一冷色，左右位置也由種子決定 |
| `swapRoundFor(seed, n, mode)` | 決定哪一輪掉包（預設最後一輪；`'random'` 模式可重現） |
| `handBack(pair, side, isSwap)` | **核心**：把使用者的點擊對應到實際被遞回來的那張卡 |
| `playRound(deck, r, side, swapAt)` | 上面兩者的組合 |
| `reasonsFor(card, seed)` | 理由選項，永遠針對「遞回來的那張」 |
| `makeRecord(hand, reason, detected)` | 一輪的紀錄 |
| `summarize(records)` | 統計；0 輪／全發現／全沒發現都不回傳 NaN |
| `verdictText(stats)` | 一句話結論，兩條路都有話講 |

結尾有 `if (typeof module !== 'undefined' && module.exports) module.exports = { ... };`，瀏覽器用一般 `<script src="engine.js">` 載入，node 也 `require` 得到，不是 ES module。

### 測試

- **單元測試**：18 組。同種子牌組完全相同、不同種子會不同、每輪一暖一冷且不重複、掉包輪保證「遞回 ≠ 選的」、非掉包輪保證「遞回 == 選的」、每張卡唯一 id 與名稱、`rounds` 參數 0／負／NaN／超大都有退路、統計函式在 0 輪／全發現／全沒發現都不吐 NaN。
- **jsdom 冒煙測試**：五條路徑——(A) 全程沒發現、(B) 關鍵輪按下「等等，這不是我選的」、(C) 中途亂點（動畫中連點、跨階段亂按、切分頁、空白字元送出）、(D) 結構與無障礙自檢、(E) 十張圖徽的座標／色彩／SVG 合法性。三條互動路徑都是 **0 個 JS 執行錯誤**，畫面無 NaN／Infinity／undefined。
