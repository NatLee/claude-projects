# 你說三天

> 一張空白的估時單。你先填一個數字，然後花五分鐘看它被一層一層拆穿。
> 最後你拿回一個修正過的數字——那個數字是你自己的歷史算出來的。

---

## 這一頁的故事線

**鉤子。** 第一屏不是標題，是一張做得像真的公文表單：格線、雙框、欄位編號 01／02、
右下角一個虛線的「核章」方格。上面只有一個問題：
**「挑一件你最近拖著、還沒做完的事。你覺得它還要多久？」**
填一個數字、選一個單位，按下「送出這張估時單」——紅色印章從天而降蓋上「已受理」。
**先讓你承諾一個數字，後面的揭穿才有力道。** 沒填之前，頁面下半部整個是鎖住的。

**第一章。** 撕開虛線，紙的世界結束，畫面換成深色的資料語言。
1994 年，有人拿同一個問題去問 37 個大四生，問的是他們的畢業論文——
這輩子他們最清楚、最在意的一件事。平均猜 33.9 天，實際 55.5 天，
只有約三成的人在自己說的日期前交出來。
然後畫面回到**你那張表的欄位 02**，把你填的數字乘上同樣的比例，
冒出一個你不會喜歡的數字。

**轉折。** 同一批學生還被要求給一個「假如什麼都不順利」的最壞情況估計：48.6 天。
一條軸上並排三個刻度，實際的 55.5 天落在最壞情況的**右邊**、想像範圍之外。
全頁最狠的一句話獨佔一個版面：
**「實際花的 55.5 天，比他們想像中最糟的版本還要久。」**

**第三章。** 拉遠鏡頭：這不是學生的毛病。1957 年雪梨也填了一張表——
700 萬澳幣、1963 年 1 月完工。長條圖長出來，實際是 1973 年、1 億 200 萬澳幣。
落差自己說話，不需要旁白。

**高潮（使用者親手觸發）。** 解藥不是更努力想細節，是換一個問法：
不要問「這次要多久」，去問「上次花了多久」。
你填進兩三筆過去的紀錄（那件事、你當時說要多久、實際花了多久），
按下「算出我的膨脹係數」——數字從 ×1.00 滾到你自己的係數，
接著把第一屏那個承諾過的估計當場修正。
**這是全頁的「哇」：那個數字不是我隨便乘的，是你自己的紀錄算出來的。**
想不起來的人有一顆備援按鈕：直接用研究平均值 ×1.6。

**留得住人的第五章。** 係數存在瀏覽器裡，變成一台可以一直用的估時器：
任何一個新的「大概三天吧」丟進去按一下就換算完成；
紀錄可增可刪；還有一條「你的係數 vs 1994 年那批學生（×1.64）」的對照長條。

**記憶點。** 一記回馬槍：
「別誤會，你沒有變準……你可以繼續說三天。但你已經知道要在行事曆上圈哪一天了。」

**視覺上的 before／after 本身就是敘事**：前半是奶油紙、襯線字、虛線格、紅色印章的公文世界；
撕開虛線之後，整頁換成深色、等寬字、細格線、克制的資料感。

## 這是什麼

一頁講**規劃謬誤（planning fallacy）**與**參考類別預測（reference class forecasting）**的
互動敘事，最後收在一個真的能長期使用的個人估時工具。類別：生活痛點小工具。

五個章節：

1. **第一章 · 你不是第一個** — 1994 年那 37 位大四生的數字，加上一張 37 點的示意圖，
   以及把你自己的估計乘上同樣比例的即時換算。
2. **第二章 · 連悲觀都不夠悲觀** — 一條 0–60 天的軸，三個刻度依序進場。
3. **第三章 · 不是只有你，是所有人** — 雪梨歌劇院的工期與造價對照長條。
4. **第四章 · 唯一有效的解藥** — 歷史紀錄表 + 個人膨脹係數計算（本頁高潮）。
5. **第五章 · 帶著走** — 係數對照長條 + 任意新估計的一鍵換算 + 紀錄管理。

## 怎麼玩

- **第一屏**：欄位 01 隨意（不填也行），欄位 02 填一個大於 0 的數字並選單位
  （小時／天／週），按「送出這張估時單」。填完之後下半部才會展開。
  之後隨時可以回去改數字或改單位，全頁的換算會即時跟著更新。
- **第四章**：預設有三列空白紀錄。每一列填「那件事」「你說要」「實際花了」「單位」。
  單位是逐列各自選的，因為算的是倍數，各列單位不必一致。
  按「＋ 再加一筆」新增（上限 12 筆），按每列右側的 `×` 刪除。
  兩個按鈕：**「算出我的膨脹係數」**（用你的紀錄）與
  **「我想不起來，先用研究平均 ×1.6」**（備援）。
- **第五章**：把任何一個新的估計丟進去按「換算」（按 Enter 也可以）。
  「清空我的紀錄與係數」可以整組重來。
- 鍵盤全程可操作，所有互動元素都有聚焦樣式；會變動的數值都掛了 `aria-live="polite"`。

## 為什麼有趣

因為規劃謬誤是少數「知道了也治不好」的偏誤之一。
研究界一再發現的一個穩健現象是：**知道有規劃謬誤這回事，並不會讓你的估計變準**。
你可以讀完這一頁，然後在十分鐘後對同事說出下一個過度樂觀的數字。

所以這一頁不勸你「多留一點緩衝」——那是意志力的說法，沒有用。
它做的是把問題換掉：從「這次要多久」換成「以前這類事情實際花了多久」。
Kahneman 與 Tversky 稱之為採取**外部觀點（outside view）**。
而使用者手上剛好有一份誰都沒有的參考類別：他自己的過去。
那個由自己歷史算出來的係數，比任何一句「要保守一點」都更難反駁。

## 完整資料來源

### Buehler, Griffin & Ross (1994)

- 出處：Buehler, R., Griffin, D., & Ross, M. (1994). *Exploring the "planning fallacy":
  Why people underestimate their task completion times.*
  **Journal of Personality and Social Psychology**.
- 受試者：**37 位**心理系大四生，預測自己**畢業論文**的完成日期。
- 平均預估：**33.9 天**
- 實際平均：**55.5 天**
- 在自己預測的日期前完成的比例：**約 30%**
- 同一批人被問「假如一切都不順利，最壞情況要多久」，平均答 **48.6 天**——
  實際的 **55.5 天比他們的最壞情況估計還要久**。

### planning fallacy 這個名字

- 由 **Kahneman 與 Tversky（1979）** 提出。
- 核心特徵：這個低估是**針對自己的**任務。同一個人去估**別人**的任務時反而準得多，
  甚至偏向高估。
- 解方是**參考類別預測（reference class forecasting）**：不要盯著這次任務的細節，
  把它放回「同類任務實際花了多久」的分布裡看。Kahneman 與 Tversky 稱之為
  採取**外部觀點（outside view）**。

### 雪梨歌劇院

- 1957 年的估計：造價 **700 萬澳幣**、**1963 年 1 月**完工。
- 實際：**1973 年**完工，造價 **1 億 200 萬澳幣**。晚了十年。

## 方法論

### 為什麼膨脹係數用幾何平均

個人膨脹係數＝各筆紀錄「實際 ÷ 預估」的**幾何平均**：

```
factor = exp( ( Σ ln(actualᵢ / predictedᵢ) ) / n )
```

不用算術平均的理由（`estimate.js` 的註解裡也寫了一份）：

1. **這是比值，不是數量。** 比值的世界裡乘法才是加法。
   一筆低估 4 倍（比值 4）配一筆高估 4 倍（比值 0.25），直覺上應該互相抵銷、係數＝1。
   幾何平均給 `sqrt(4 × 0.25) = 1`；算術平均給 `(4 + 0.25) / 2 = 2.125`，
   憑空多出一倍的膨脹。
2. **比值的分布天生右偏。** 往下最多壓到 0，往上可以到 200 倍。
   算術平均會被少數幾筆災難級紀錄綁架，幾何平均對它們溫和得多。
3. **幾何平均＝對數空間的算術平均**，而人對時間的誤判本來就比較接近對數尺度。

### 單位換算

- 1 小時 = 1 小時、1 天 = **24 小時**、1 週 = **168 小時**（曆日，不是工作日）。
  論文那組數字算的是日曆天，所以這裡跟著用曆日，語意才一致。
- 歷史紀錄的單位**逐列各自選**，計算時單位會自然消掉（比值無單位），
  所以各列不必一致。

### 邊界處理（全部有 node 斷言覆蓋）

| 情況 | 行為 |
|---|---|
| 空紀錄陣列、非陣列 | `inflationFactor()` 回 **`null`**（不是 NaN、不是 1），呼叫端才能走備援 |
| `predicted` 為 0 或負數 | 該筆整個被忽略，其餘照算 |
| `actual` 為 0 或負數 | 同上 |
| 非數字輸入（`'abc'`、`NaN`、`Infinity`、`null`、物件……） | `parseAmount()` 一律回 `null`，畫面顯示 `—` |
| 只有一筆紀錄 | 就是那一筆的比值 |
| 極端值（預估 1 小時、實際 200 小時） | 單筆比值夾在 `[0.02, 100]`，仍算得出有限的係數 |
| 全部準時（predicted === actual） | 係數剛好 `1` |
| 第一屏填 0 或負數 | 擋下來、給訊息，不展開下半部 |
| 時間格式化 | 用整數（總分鐘／總小時／總天）做進位，不會出現「3 小時 60 分」「2 天 24 小時」 |

畫面上任何位置都不會出現 `NaN` 或 `Infinity`；jsdom 測試對整頁可見文字做了全文掃描。

## 技術註記

- 純靜態、自包含，雙擊 `file://` 可開。無 `type="module"`、無 `fetch()`、無外部資源、無函式庫。
- 檔案：`index.html`（入口，含內嵌 CSS 與行為層）、`estimate.js`（純函式）。
  `estimate.js` 用一般 `<script src>` 載入，同時支援
  `module.exports`，所以 node 也 `require()` 得到。
- **沒有用 canvas。** 37 點示意圖與時間軸是 SVG，長條圖是純 CSS。
  SVG 一律純色描邊（沒有 `stroke:url(#…)` 漸層描邊），漸層只用在 CSS 填色；
  沒有掛在零面積路徑上的 `drop-shadow`。
- 動畫只用 `transform` / `opacity`。長條與結果區重播採
  「`transition:none` → 設隱藏 → 讀 `getBoundingClientRect()` 強制 reflow →
  下一個 `requestAnimationFrame` 才開 transition」的順序，確保每次都會播。
- 捲動進場用 `IntersectionObserver`（沒有綁 scroll 事件）。
  `window.matchMedia`、`IntersectionObserver`、`requestAnimationFrame`
  三者都做了 `typeof` 檢查與退路：任何一個不存在，頁面照樣完整可用，
  只是直接顯示終值、不播動畫。
- `prefers-reduced-motion` 完整降級，並用
  `matchMedia(...).addEventListener('change', ...)`（舊瀏覽器退回 `addListener`）動態追蹤。
- `document.hidden` 時暫停 CSS 動畫，數字滾動直接跳終值。
- 無障礙：真的 `<button>` / `<input>` / `<label>`、鍵盤可操作、`:focus-visible` 樣式、
  `aria-label`、變動數值 `aria-live="polite"`、SVG `role="img"` + `aria-label` 並附文字版摘要。
  **顏色不是唯一資訊**：37 點圖用實心／空心區分，長條圖每一條都標了文字數值。
- 手機 <560px 單欄可讀，紀錄表在窄螢幕會重排成「名稱一列、三個數字一列」，輸入框加大好按。

### localStorage

- 前綴：`planfall_`。實際使用的 key 只有一個：**`planfall_state`**。
- 內容：`{ records, factor, factorSource, estValue, estUnit, taskName }`。
  也就是你的歷史紀錄、算出來的係數（以及它是來自個人紀錄還是研究平均值）、
  第一屏那張估時單填的內容。
- 讀寫都包在 `try/catch` 裡，無痕模式或停用 localStorage 時不會讓頁面壞掉，
  只是重新整理後要再填一次。
- 頁面上的「清空我的紀錄與係數」按鈕會把這個 key 移除。

### 測試

- `node --check estimate.js` — 通過。
- 純函式斷言（`require('assert')`）：15 組，涵蓋 1.637 基準值、全部準時 → 1、
  空陣列回 null、predicted/actual 為 0 或負數被擋、單筆、幾何平均抵銷性質（0.5 與 2 → 1）、
  極端值、`applyFactor` 單調遞增、`toHours` 三種單位換算、
  `formatDuration` 全掃描 12,000 次確認沒有 60 分／24 小時／7 天的進位殘留。
- jsdom 冒煙測試：19 個步驟兩輪（一輪連 `requestAnimationFrame` 都沒有，
  一輪有 rAF），涵蓋填表 → 揭穿 → 加三筆紀錄 → 算係數 → 塞非數字與負數 →
  極端值 → 刪紀錄 → 全刪 → 備援 ×1.6 → 換算器 → localStorage → 清空 → 重新載入。
  **0 個 JS 執行錯誤**，可見文字中沒有 `NaN` / `Infinity`。
