# 硬幣的鋸齒

## 這頁的故事線

- **鉤子**：近全黑的畫面，中央只有一枚硬幣邊緣的極端特寫——一排發亮的銀色鋸齒。標題只問一句：「邊緣為什麼是鋸齒的？」然後不解釋、直接下重手：「因為三百年前，有人正在偷你的錢。用剪刀。」
- **鋪陳**：1690 年代倫敦鑄幣廠的檢驗桌。桌上放著一枚 1662 年以前的手工錘打銀幣，歪歪扭扭，重量 100%。旁邊有一把剪刀。
- **共犯**：你親手剪。天平掉下去，店家照收——因為錘打幣本來就長得歪七扭八，沒有人知道一枚「正常的」先令應該長什麼樣子。剪五刀掉到 78.5%，碎銀慢慢堆起來，而檢驗結果始終寫著「通過」。
- **轉折**：問題是全國都在剪。到 1690 年代中，流通的舊銀幣普遍只剩法定重量的一半上下，物價亂掉、貿易停擺。1696 年政府下重手：全國回收重鑄。
- **高潮（必須由使用者按下）**：新幣上桌——機器壓製、正圓、邊緣 120 道整齊的滾花與拉丁刻字 DECUS ET TUTAMEN。你**拿起同一把剪刀再剪下去**：鋸齒被剪斷 18 道，邊緣展開圖破一個洞，刻字少了三個字母，紅色 TAMPERED／已遭剪損 當場蓋上去。而重量只掉 2.0%——是你剛才隨便一刀的 1/2.5。**削得比較少，卻藏不住了。**
- **抓你的人**：而負責抓你的，是艾薩克・牛頓。喬裝進酒館蒐證、訊問一百多人、送出 28 個定罪，多數上絞刑台——當時破壞王室貨幣是叛國罪。
- **記憶點**：鏡頭拉遠到今天。你手上的硬幣裡早就沒有貴金屬，鋸齒完全失去原本的意義，但它還在，而且數目精確：一角 118 道、二十五分 119 道、半元 150 道。它現在留著不是為了防賊，是為了讓看不見的人也摸得出來手上是多少錢。回扣開頭那個問題：答案有兩個，中間隔了三百年，一個是防你伸手，一個是讓你摸得到——同一圈鋸齒。

## 這是什麼

一個可以親手操作的歷史現場：1690 年代倫敦皇家鑄幣廠的檢驗桌。你會先當一次剪錢賊（在錘打幣上剪，沒人抓得到），再當一次被抓的人（在機製新幣上剪同一刀，一眼露餡）。核心論點只有一句：

> 鋸齒擋不住剪刀。鋸齒擋住的是「沒有人看得出來」。

它把「重量」這個看不見的量，轉換成「形狀」這個看得見的量——提供一個所有人都認得、一眼可對照的**基準**。沒有基準，就沒有證據。

## 怎麼玩

1. 往下捲，看檢驗桌上那枚 1662 年以前的錘打先令。硬幣、邊緣展開圖、天平讀數都在右邊（手機在上方）。
2. **第二章**：按「剪一刀」，最多五刀。看重量掉、碎銀堆高，而判定欄始終是綠色的「通過」。按「熔掉，再拿一枚」可以換一枚新的舊幣，碎銀會累積下去。
3. **第三章**：純敘事的轉折，不用點。
4. **第四章**：按「換上 1696 年的新幣」——硬幣換成正圓、有滾花與刻字的機製幣。然後按「還是剪下去」，這是全頁的高潮。
5. **結尾**：點三顆現代美國硬幣的籌碼，看 118／119／150 道鋸齒實際畫出來的樣子。

## 為什麼有趣

因為「哇」的那一刻不是頁面播給你看的，是你自己造成的，而且是**同一個動作、兩種結果**：

| | 錘打幣（1662 前） | 機製幣（1696 後） |
| --- | --- | --- |
| 你剪的那一刀 | 重量 −4.6% | 重量 −2.0% |
| 邊緣看得出來嗎 | 看不出來 | 鋸齒斷 18 道、刻字缺 3 個字母 |
| 檢驗結果 | 通過 | TAMPERED |

你偷得比較少，卻被抓到了。這就是「防偽」的真正機制：不是讓犯罪變困難，是讓犯罪變可見。

然後再補一刀：抓你的人是牛頓。

## 方法論：幾何與重量怎麼算

全部在 `geometry.js`，是不碰 DOM 的純函式，node 可直接 require。

**1. 硬幣 = 一圈極座標取樣點**

把輪廓當成 N 個角度上的半徑（頁面用 720 點，機製幣用 1080 點，結尾的現代硬幣用 1440 點）。每個角度的半徑由三層疊起來：

```
r(θ) = base(θ) + 鋸齒(θ)   然後對每一刀取 min
```

- `base(θ) = radius × (1 + wobble(θ))`。錘打幣的 `wobble` 是四個正弦波疊加（3ω/5ω/8ω/13ω），振幅 5.2%，由 seed 決定，完全可重現——這就是「手工敲出來，每一枚都不一樣」。機製幣 `wobble = 0`，正圓。
- 鋸齒是週期性凸起：`0.5 × (1 − cos(2π·frac))`，每 `360/teeth` 度一齒（頁面主幣 120 齒＝每 3 度一齒），高度為半徑的 3.6%。錘打幣 `teeth = 0`。

**2. 「被剪掉的一段」= 一條弦**

`addCut(coin, centerDeg, sweepDeg, extraDepth)` 記下一條與中心距離 `dist = radius × cos(sweep/2) − extraDepth` 的弦。某個角度的半徑是

```
r(θ) = min( 未剪半徑(θ),  dist / cos(θ − center) )
```

角度差用 `norm180()` 正規化到 (−180, 180]，所以剪痕跨越 0 度不會出事（測試裡專門驗了 0°、±3°、±180°、357°、720°、−721°）。

用 `min()` 而不是「把該區間半徑設成定值」有一個好處：**鋸齒是被弦自然削掉的**，不需要另外寫「這段不畫齒」的分支——剪刀在物理上做的正是這件事。`isCutAt()` 就是比較「剪後半徑」與「未剪半徑」，`brokenTeeth()` 統計被削到的角度總和除以每齒角度。

**3. 重量 = 面積比（shoelace）**

把取樣點轉成 (x, y)，用 shoelace 公式算多邊形面積，除以同一枚硬幣「沒有任何剪痕」時的面積：

```
weightRatio = area(有剪) / area(無剪)
```

因為分子分母用同一條取樣路徑計算，沒剪過時**嚴格等於 1**（不是 0.9999）。取樣夠密時這個近似很準：3600 點的正圓與 πr² 相對誤差 5.08 × 10⁻⁷。

實際數字：錘打幣一刀（sweep 55°、extraDepth 10）約掉 4.6%，五刀後 78.5%；機製幣那一刀（sweep 30°、extraDepth 8）只掉 2.0%，卻剪斷 18 道齒、蓋掉 3 個刻字字母。**這個 2.5 倍的落差就是全頁的論點，是算出來的，不是寫死的。**

**4. 邊緣展開圖**

`edgeProfilePath()` 把整圈邊緣攤平：x 軸是角度 0→360°，y 軸是半徑偏差（向外放大 7 倍、向內放大 2.4 倍，讓鋸齒與缺口在同一張圖上都看得清楚）。刻字用 16 個 `<text>` 依角度排在下方，每個字母查一次 `isCutAt()` 決定要不要變暗——所以「刻字缺了三個字母」是幾何算出來的，不是預先寫好的。

## 技術註記

- 純靜態、自包含、`file://` 雙擊可開。**零外部資源**：沒有 CDN、沒有字型檔、沒有 `fetch()`、沒有 `type="module"`。`geometry.js` 用一般 `<script src>` 載入，結尾以 `module.exports` 同時支援 node。
- **不用 canvas**。硬幣、邊緣展開圖、首屏特寫全部是 SVG `<path>`，`d` 由 `geometry.js` 產生。
- **localStorage：完全沒有用到。** 這頁不需要記住任何東西——重新整理就是回到 1662 年，本來就該這樣。（若日後要加，前綴一律 `coinedge_`。）
- SVG 地雷處理：所有漸層都是 `gradientUnits="userSpaceOnUse"` 加實際座標；**沒有任何漸層描邊**（`stroke` 一律純色）；`drop-shadow` 只掛在群組 `<g class="coinG">`，不掛在個別路徑；沒有使用 dasharray 描線動畫，所以不存在倒放／首幀閃現問題。
- 動畫只動 `transform` 與 `opacity`。數字滾動用 rAF，每幀一次，`document.hidden` 時直接跳終值；`visibilitychange` 會把 CSS 動畫整批暫停。
- `prefers-reduced-motion` 完整降級，並用 `matchMedia(...).addEventListener('change')` 追蹤（有 `addListener` 舊介面退路）。**防呆**：`window.matchMedia`、`IntersectionObserver`、`requestAnimationFrame` 任何一個不存在，頁面都照常運作（IO 缺席時所有進場元素直接顯示，rAF 缺席時走 `setTimeout`）。jsdom 剛好三者都缺，冒煙測試就是拿它驗的。
- 捲動進場用 `IntersectionObserver`，全頁 **0 個 scroll 事件監聽**。
- 無障礙：7 個互動元件全是真 `<button>`，鍵盤可操作、有 `:focus-visible` 樣式、有 `aria-label`；結尾的硬幣籌碼用 `aria-pressed` 做單選群組。讀數區是 `aria-live="polite"`，但滾動中的數字標了 `aria-hidden`，另外給一段 `.sr-only` 摘要在每次互動結束後一次唸完，避免逐幀報數。
- 手機 <560px 單欄可讀；<940px 時檢驗桌壓成「硬幣在左、讀數在右、展開圖橫跨底部」的緊湊列並吸附在頂端，硬幣與展開圖都不會溢出。
