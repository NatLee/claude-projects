# 腦子裡那件一直在吵的事

> 沒做完的事會一直在腦子裡吵。而讓它閉嘴的方法，不是把它做完，是替它訂一個具體的計畫。

類別：生活痛點小工具　·　日期：2026-07-30

---

## 故事線

這一頁的容器形式，是**一份會自己冒出來吵你的待辦清單**——頁面本身就是那個吵你的東西。

### 鉤子：讓它真的在畫面上敲一次門

第一屏不講名詞、不下定義，只描述一個所有人都有的經驗：
「你正在做別的事。手上這件其實很順，你甚至有點進入狀況了。然後——」

停在這裡一秒半，一張紙條**真的從畫面下方浮上來**，輕輕晃著：
「那封信，你還沒回。」旁邊一個小圓點一圈一圈往外敲。

接著才收尾：它沒有變大聲，也沒有多說什麼，它只是又敲了一次門，然後退回去，等下一次。
讀者已經先「看見」了這個效應，才會想知道它叫什麼。

### 第一章：1927 年那頓飯

Kurt Lewin 在餐廳裡的觀察——服務生記得住還沒結帳的桌子，帳一收就忘光。
這裡刻意寫成**著名的起源軼事**，不是實驗數據。

桌上三張點餐單是可以按的：按下「結帳」，那張單子就褪色、蓋上「已結帳」，
品項整組消失、換成一句「……剛剛點了什麼來著？」。三張都結完之後跳出一句追問：
「現在不要往上看——桌 7 剛剛點了什麼？」

然後才進正題：Bluma Zeigarnik 1927 年的實驗。

### 第二章：換你（互動）

八題很短的小事：把三個字重排成詞、數畫面上有幾個圓點、兩個數字相加、一排符號裡找出不一樣的那個。
沒有計時器、沒有分數、答錯也只會說「沒關係」。

其中**四題會在你做到一半時自己跳走**（畫面蓋上一句「先跳過，換下一題」）。
跑完之後問你：剛剛那些題目，你記得哪幾題？給一份順序打亂的清單讓你勾。

揭曉的是**你自己的結果**，照實呈現，不預設方向。詳見下面的〈誠實說明〉。

### 第三章：轉折（這一頁最重要的一章）

坊間把 1927 年的結論講成一條定律。近年的統合分析把它拆成兩半：
**「記得比較牢」沒有找到；「想回去把它做完」有，而且普遍。**

所以真正在吵你的，可能不是「你記得它」，是**它還開著**。
這個轉折同時也是後半段工具的前提——如果吵你的是記憶，那你只能等它淡掉；
如果吵你的是一件事還開著沒收，那就有辦法了。

### 高潮：由使用者親手觸發的「安靜下來」

Masicampo & Baumeister (2011) 的發現：讓念頭安靜下來**不需要把事情做完**，
只要替它訂出一個具體的計畫就夠了。

工具照這個規格做。你把腦子裡正在吵的事丟進「吵鬧區」，卡片會用很輕微的幅度晃著、
帶著一顆 ⟡ 和「還在吵」的標記。它只逼你填三格：**下一步是什麼、什麼時候、在哪裡**。

三格都填了，「排定」才會生效。按下去的那一刻——卡片停止晃動、微微放大再縮小、
褪去、然後從左邊的吵鬧區**搬到右邊的「已排定」**，換上冷靜的青綠色和「✓ 已排定」。
這是全頁的「哇」：**「安靜下來」這件事，看得見。**

### 記憶點：回馬槍

最後回扣第一屏那個一直來敲門的念頭：

> 你以為它在催你動手。它不是。它從頭到尾只問同一句話：「你確定你不會忘記我嗎？」
> 所以你不必回答「我馬上做」。你只要回答得夠具體——
> 下一步·寫開頭那一句／什麼時候·星期四早上，倒完咖啡之後／在哪裡·廚房那張桌子。
> 然後它就會走開。它要的從來就只是一個確認。

## 這是什麼

一頁純靜態的捲動敘事，同時是一台真的能用的小工具。
主題是蔡加尼克效應（Zeigarnik effect）——以及它近年被統合分析修正掉的那一半，
還有真正站得住的那個解法：**具體計畫**。

雙擊 `index.html` 就能開，不需要伺服器、不連任何外部資源。

## 怎麼玩

1. **第一屏**：什麼都不用做，等一秒半，看那張紙條自己浮上來。
2. **第一章**：按三張點餐單上的「結帳」，看它們一張一張被忘掉。
3. **第二章**：按「開始這八題」。
   - 重排三個字：照順序點三個字。
   - 兩個數字相加 / 數一數：點一個選項。
   - 找出不一樣的：點那個空心／倒過來的符號。
   - 有幾題會自己跳走，不用管它。
   - 跑完後勾出你記得的題目，按「揭曉」。
   - 想再跑一次就按「換一組題目再跑一次」（會換一組新的亂數種子）。
4. **第四章（工具）**：
   - 在上面那格寫一件正在吵你的事，按「丟進來」。
   - 卡片會落到左邊的「吵鬧區」，計畫表單自動展開。
   - 填三格：下一步是什麼 / 什麼時候 / 在哪裡。少一格、或只打空白都不算數，
     下方會告訴你還缺哪幾格。
   - 三格都有了就按「排定，讓它安靜」，看它搬過去。
   - 已排定的卡片可以「改計畫」、「標記完成」、「刪除」；整份清單可以「清空」（需要確認一次）。
5. 清單會留在這台裝置上，下次回來還在。

鍵盤也可以：所有操作都是真的 `<button>` 與 `<input>`，Tab 走得到，Enter 在三格裡任一格按下就等於按「排定」。

## 為什麼有趣

- **頁面本身就是那個吵你的東西**。它先示範一次，再解釋自己在幹嘛。
- **第二章讓你變成受試者**，而不是讀一段別人的實驗摘要。
- **第三章敢自砸招牌**。多數談蔡加尼克效應的文章會停在 1927 年那個漂亮的結論；
  這一頁把統合分析的修正講出來，故事反而更好看——因為被砍掉的那一半，
  正好把讀者推向真正有用的那一半（Ovsiankina 效應與「它還開著」）。
- **解法反直覺，而且成本極低**：不是叫你去做完，是叫你花二十秒寫三格。

## 誠實說明（請務必連著讀）

### 第二章是 n=1 的示範，不是證據

一個人、八題、跑一次。不管跑出哪個方向，都可能只是你今天比較分心，
或那幾題剛好比較好記。它沒有對照組、沒有樣本數、沒有統計檢定。

**頁面不會宣稱「你一定會記得被打斷的那些」**——它只照實顯示你自己的勾選結果，
兩邊一樣多、甚至反過來，都會照實寫出來（頁面對「被打斷的多」「做完的多」
「一樣多」「一題都沒勾」「這輪沒有任何一題被打斷」各有各的說法）。
第二章的結果區裡就直接寫著這一段，而且當場預告第三章的翻案。

### 原始效應在統合分析中並不穩固

近年一份探討蔡加尼克效應與 Ovsiankina 效應的統合分析，
**並沒有發現被打斷任務的記憶優勢**——也就是「沒做完的事你會記得比較牢」這件事，
在整批研究看下來並不成立，或至少遠比流傳的版本弱、也更看情境。

同一份統合分析**確實找到了一個普遍的「回頭把它做完」的傾向**（Ovsiankina 效應）。

所以這一頁的立場是：
**記憶優勢那一半打折扣，「還開著會拉著你」那一半站得住，而具體計畫這個解法有自己的證據來源（2011）。**
頁面沒有引用任何未經查證的統計數字、樣本數或效果量。

### 這一頁談的不是症狀

談的是待辦事項與工作記憶，不是焦慮症、不是強迫思考，也不宣稱能改善任何症狀。
如果腦子裡重複的念頭已經影響睡眠或日常生活，那不是一張清單能處理的事。

## 完整資料來源

1. **Zeigarnik, B. (1927).** *Über das Behalten von erledigten und unerledigten Handlungen*
   （論已完成與未完成動作的保持）, *Psychologische Forschung*, 9, 1–85.
   受試者被交付一連串短時間的活動，其中一些在完成前被打斷；
   事後受試者**回憶起被打斷的任務多於已完成的任務**。這就是後來所說的蔡加尼克效應。

2. **起源軼事：Kurt Lewin 與餐廳服務生。**
   Zeigarnik 的老師 Kurt Lewin 注意到餐廳服務生對尚未結帳的訂單記得特別清楚，
   帳結完就忘了。這是這項研究**著名的起源軼事**，不是論文裡的實驗數據——
   頁面第一章也是照這個口氣寫的。

3. **近年的統合分析**（探討蔡加尼克效應與 Ovsiankina 效應）：
   **沒有發現被打斷任務的記憶優勢**，但**找到了一個普遍的「回頭把它做完」的傾向**
   （即 Ovsiankina 效應）。換句話說，原始效應比流傳的版本弱得多，也更看情境。

4. **Masicampo, E. J., & Baumeister, R. F. (2011).**
   *Consider it done! Plan making can eliminate the cognitive effects of unfulfilled goals.*
   *Journal of Personality and Social Psychology*, 101(4), 667–683.
   帶著未完成目標的受試者，在無關的閱讀作業中會出現**更多與該目標有關的念頭**、
   與目標有關的字詞**心理可及性更高**，有時在另一項字謎作業上**表現更差**；
   而**替未完成的目標訂出具體計畫，可以顯著減少這些侵入性的念頭**。

頁面本文只留一行來源掛名（footer），完整出處在這裡。

## 技術註記

### 檔案

```
index.html   單檔自包含（樣式內嵌、頁面邏輯內嵌），約 1,100 行
engine.js    純函式引擎，不碰 DOM、不碰 localStorage、不看時鐘
說明.md      本檔
```

`engine.js` 用一般的 `<script src>` 載入，**不是 ES module**，也沒有任何 `fetch()`，
所以雙擊 `file://` 直接可以開。沒有任何外部資源（連 cdnjs 都沒用到）。

### engine.js 的公開函式

| 函式 | 做什麼 |
| --- | --- |
| `makeRng(seed)` / `hashSeed(seed)` | mulberry32 亂數；種子可以是數字或字串 |
| `generateTasks(seed, count)` | 產生第二章的小任務。**同種子必定產生完全相同的題目** |
| `decideInterrupted(seed, count, k)` | 決定哪幾題被打斷（回傳排序好的索引；第 0 題盡量留給使用者做完） |
| `applyInterrupts` / `splitTasks` | 蓋上旗標、拆成「被打斷 / 已完成」兩組 id（互斥、聯集為全體） |
| `recallOrder(seed, tasks)` | 回想清單的呈現順序，跟作答順序不同但一樣可重現 |
| `buildRun(seed, opts)` | 一次組好一輪（題目 + 打斷名單 + 回想順序） |
| `recallStats(tasks, checkedIds)` | 兩組各記得幾題、百分比、方向。**任何輸入都不會回傳 NaN／Infinity** |
| `isScheduled(todo)` | **三格（step / when / where）都有實質內容才 true** |
| `missingFields` / `missingLabel` / `planLine` | 缺哪幾格、提示文字、一句話計畫摘要 |
| `makeTodo` / `sanitizeTodos` / `parseStore` | 建立與還原待辦；壞掉的 JSON 只會拿到空陣列 |
| `summarize(todos)` | 吵鬧 / 已排定 / 已完成 的計數 |

結尾是 `if (typeof module !== 'undefined' && module.exports) module.exports = {...}`，
所以同一份檔案在瀏覽器（掛 `window.Zeigarnik`）和 Node（`require`）都能用。

### localStorage

全部用 `zeigarnik_` 前綴，讀寫刪一律包在 try/catch 裡；
被瀏覽器擋掉（例如 opaque origin、無痕模式限制）時整頁照常運作，只是不留下資料。

| key | 內容 |
| --- | --- |
| `zeigarnik_todos_v1` | 第四章的清單，JSON 陣列。每則是 `{id, what, step, when, where, done}` |
| `zeigarnik_seed_v1` | 第二章目前使用的亂數種子（按「換一組題目」會換一個新的） |

還原時一律先過 `parseStore()`：不是 JSON、不是陣列、元素不是物件、`what` 是空白的、
id 重複、欄位超長——全部會被清乾淨或丟掉，最多保留 60 則。

### 動畫與效能

- 所有動畫只動 `transform` 與 `opacity`（晃動、敲門、進場、「安靜下來」的收合都是）。
- 沒有綁任何 `scroll` 事件；捲動進場用 `IntersectionObserver`。
- rAF 用一個 `onFrame()` 節流器包起來，同一幀內的多次要求只跑一次。
- `document.hidden` 時整頁動畫 `animation-play-state: paused`，
  第二章「被打斷」的倒數也會暫停、回到分頁時接著算（用 `performance.now()` 記帳，不是 `Date.now()`）。
- 「一直在吵」的晃動幅度是 ±0.34 度、週期 5.8 秒起跳，卡片被聚焦（focus-within）時自動停下來，
  刻意做得很輕微，不會變成畫面上抖個不停的干擾。

### prefers-reduced-motion 與防呆

- `matchMedia('(prefers-reduced-motion: reduce)')` 用 `addEventListener('change', …)` 追蹤，
  舊瀏覽器退回 `addListener`。開啟時：晃動整個關掉、進場動畫關掉、
  第一屏那張紙條直接靜態顯示並改用文字標示「它又浮上來了」、
  「安靜下來」改成瞬間搬移。**吵鬧／已排定的區別本來就有文字標記，不靠動畫也不靠顏色。**
- `window.matchMedia`、`IntersectionObserver`、`requestAnimationFrame`
  三者任一不存在都不會讓頁面掛掉：全部先 `typeof` 檢查再用，各有退路
  （沒有 IO 就直接把所有區塊設為可見；沒有 rAF 就退回 `setTimeout`）。

### 無障礙

- 全部是真的 `<button>`、`<input>`、`<label for>`；鍵盤可完整操作；有 `:focus-visible` 樣式。
- 狀態變化透過兩個 `aria-live="polite"` 區域播報（第二章進度與結果、第四章清單變化）。
- **顏色不是唯一資訊**：「還在吵」有 ⟡ 與文字標籤與虛線框，「已排定」有 ✓ 與文字標籤，
  「已完成」有文字標籤與刪除線；第二章的進度圓點是純裝飾並標了 `aria-hidden`。
- 數圓點的 SVG 有 `role="img"` 與 `aria-label`（刻意不透露數量）；
  找不一樣的按鈕每顆都有描述性的 `aria-label`。
- 手機 <560px 單欄可讀，輸入框與按鈕維持好按的尺寸。

### 刻意不做的事

沒有連續達成天數、沒有逾期紅字、不會計算「這件事你放了幾天」。
這台工具的目的是讓你少一件煩的事，不是多一件。
