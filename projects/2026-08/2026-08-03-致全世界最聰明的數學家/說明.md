# 致全世界最聰明的數學家 · 最速降線

**類別**：科學趣聞　　**日期**：2026-08-03
**敘事容器**：分章旅程（五幕逐步解鎖）＋ 期刊挑戰書／匿名信的假文件框架
**互動形式**：押注 → 觀看賽跑 → 徒手繪製路徑對戰 → 滾輪揭曉 → 等時線同步落底

---

## 這一頁的故事線

- **鉤子**：不解釋任何東西，直接把 1696 年那段點名全歐洲的挑戰甩在臉上——「致全世界最聰明的數學家」。寫的人知道答案，他不打算說。
- **鋪陳**：三條軌道請你先押一注。你多半會押「最短的那條」。
- **轉折**：直線輸了，而且輸給那條「一開始就把自己摔下去」的軌道。看起來最優雅的緩降弧慢了六成五。最短的路和最快的路是兩件事。
- **高潮（使用者親手觸發）**：換你畫。手指從 A 拖到 B，畫完放手，你的珠子跟「那位匿名者的曲線」並排滑下去。你可以一直重畫，但永遠追不過那條金線——那是有得證的。
- **揭曉**：那條線不是誰發明的。按下「放輪子」，一顆輪子沿著天花板滾過去，輪緣上的粉筆把它一筆畫出來。擺線。
- **回馬槍**：同一條曲線翻過來做成碗，五顆不同高度的珠子同時落底——等時線。惠更斯 1659 年就撿到過同一條曲線，為的是做一個走得準的鐘。
- **記憶點**：1697 年 1 月 29 日下午四點到隔天凌晨四點，一個在造幣廠上班的五十四歲男人花十二小時解完，寄出時沒有署名。伯努利只讀了幾行：「從爪子，我認得出獅子。」最後鏡頭拉遠——你每天推出門的腳踏車，輪子邊緣那一點正在空氣裡畫著全世界下坡最快的路。

## 這是什麼

最速降線問題（brachistochrone，希臘文 *brachistos* 最短 ＋ *chronos* 時間）的互動敘事版：
在垂直平面上給定兩點 A、B，求一條曲線使無摩擦質點在重力下從 A 滑到 B 的時間最短。答案是**倒過來的擺線**。

## 怎麼玩

1. **第一幕**：先在 A／B／C 三條軌道裡押一注，按「放手」看三顆珠子同時出發。
2. **第二幕**：在畫布上從 A 按住拖到 B 畫一條你自己的路徑，放手後按「放手」跟擺線比一場。可以無限重畫；最佳成績（與擺線的時間差百分比）會記在瀏覽器裡。
   - 鍵盤使用者：按「改用滑桿」，用左右方向鍵調整曲線的下凹程度（指數 1.8 → 0.20，最佳落在 0.43 附近，可逼近到與擺線差 0.9%）。
3. **第三幕**：按「放輪子」，看擺線被一顆滾動的輪子畫出來。
4. **第四幕**：按「放手」，五顆不同高度的珠子在擺線碗裡同時通過最低點。重合的那一刻畫面會停一拍，五顆疊成同心圓環（真的在同一點，只是疊成一顆會看起來像少了四顆），然後繼續往另一側盪，每次通過底部都還是一起。
5. **第五幕**：那封沒有署名的信。

## 為什麼有趣

三個層層遞進的反直覺：

1. **最短 ≠ 最快**。直線是最短的路，卻不是最快的；先把高度換成速度，後面那段長路才跑得快。
2. **答案是一個「副產品」**。擺線不是為了這題設計出來的形狀，它只是輪子上一點滾一圈的軌跡，卻剛好是變分問題的解。
3. **同一條曲線兼任兩個角色**。它同時是最速降線（brachistochrone）與等時線（tautochrone）——後者早在 1659 年就被惠更斯為了做鐘而發現。

再加上一個科學史上最漂亮的橋段：匿名的解答、一句 *tanquam ex ungue leonem*。

### 物理與數值方法（`physics.js`）

- 能量守恆：珠子在相對釋放點下降 h 處的速率 v = √(2gh)，無摩擦、無滾動慣量。
- 折線滑降時間：單一直線段內沿線方向加速度為定值，故 `t = 2·ds/(v₁+v₂)` 對該線段是**精確**的，誤差只來自把曲線離散成折線。
- 擺線求解：x = r(θ − sinθ)、y = r(1 − cosθ)，由 (Θ − sinΘ)/(1 − cosΘ) = Δx/Δy 二分法解 Θ（該函數在 (0, 2π) 嚴格遞增），再得 r = Δy/(1 − cosΘ)。解析時間 T = Θ√(r/g)。
- 等時線：碗 x = r(φ + sinφ)、y = r(1 + cosφ)，沿弧長 s = 4r·sin(φ/2) 的運動是**嚴格**簡諧，故 sin(φ/2) = sin(φ₀/2)·cos(ωt)，ω = √(g/4r)，四分之一週期 T = π√(r/g) 與釋放高度無關。（注意不是 φ 本身做簡諧運動——動畫若寫成 φ = φ₀cos(ωt) 會在大振幅時明顯失真。）
- 物理一律在正規化世界座標（A=(0,0)、B=(1, 0.62)、g = 2.0）計算，只有繪圖才換算成像素，因此顯示的秒數與螢幕大小、裝置無關。

### 驗證（node 斷言，開發時執行）

1. 直線折線積分 = 解析解 L√(2/gΔy)（誤差 < 1e-9）。
2. 垂直自由落體 = √(2Δy/g)。
3. 五組 (Δx, Δy) 的擺線：折線積分 vs 解析 Θ√(r/g)，相對誤差 < 2e-6；終點座標誤差 < 1e-9。
4. 擺線嚴格快於同端點直線。
5. **最速性**：對擺線施加 395 條隨機正弦擾動（端點釘死），全部慢於擺線，無一例外。
6. 三條候選軌道的排序：凸弧 > 直線 > 凹弧 > 擺線（時間由長到短）。
7. 等時線：五個不同釋放角在 t = π√(r/g) 時 φ 皆歸零（誤差 < 1e-9），另以獨立能量積分交叉驗證三個高度（相對誤差 < 2e-4）。
8. 邊界：上坡、單點、水平起步皆正確判定為無解。
9. `pointAtTime` 端點正確且 x 單調不減。

## 視覺驗證

除了 node 斷言，另外把四張 canvas 的繪圖指令錄下來、用 PIL 光柵化成 PNG 逐幕看圖，抓到並修掉三個肉眼才看得出來的問題：

1. **每一幕解鎖前是 `display:none`，畫布量到 0×0**。原本只靠 ResizeObserver 在轉為可見時回呼來重新量測，時機不保證，第三幕因此停在 1×1 的畫布上完全空白。改為在 `reveal()` 解鎖後（rAF 內、版面已算好）主動重量測，並在每次「放手／放輪子」與起筆前再同步一次。
2. **第四幕的碗畫反了**：`y` 在畫布座標又翻了一次，變成一座拱門，珠子往「上」聚。物理沒錯（ω 與畫法無關），純粹是繪圖把 `r(1+cosφ)` 多減了一次。
3. **重合的瞬間只剩一顆珠子**：五顆疊在同一點時只看得到最後畫的那顆，讀起來像「其他四顆消失了」。珠子改為永遠實心不消失，快重合時再連續地疊上同心圓環（環的粗細由實際間距算出，不是開關切換）；第一次落底把時間按住 0.55 秒，期間圓環持續往外擴散淡出，看起來是撞擊而不是當機。
4. **輪子轉向看不出來**：粉筆點與輪輻的旋轉方向本來就都是逆時針（量測：粉筆時鐘位置 12.00 → 11.07 → 10.15 → 9.22 → 8.30 → 7.37 → 6.45，79 幀全逆時針、0 幀順時針），但六根輪輻每 60° 完全重複、粉筆那根又剛好疊在其中一根上，眼睛沒有可追的參考點。輪輻整體偏 30°，再在輪胎上加一段跟在粉筆後面、逐段淡出的拖尾亮弧，打掉旋轉對稱。

同一套錄製也在「ResizeObserver 永不回呼、隱藏中畫布回傳 0×0」的環境跑過 820×340 與 330×230 兩種尺寸，四張畫布都畫在正確的座標範圍。

## 已知渲染地雷的處理

- canvas 由 CSS 決定尺寸（`height: clamp(...)`），dpr 回寫 `width/height` 屬性前先比對是否相等；`ResizeObserver` 也先比對整數化後的寬高才回呼，避免每幀翻倍導致畫面消失。
- 動畫由單一 rAF 排程器驅動，沒有任務就不轉；`visibilitychange` 分頁隱藏時停止累積時間，`IntersectionObserver` 離屏暫停。
- 沒有使用 SVG 漸層描邊與 dasharray 動畫，故不涉及該兩類地雷；canvas 的 `shadowBlur` 一律包在 `save/restore` 內，不影響其他筆畫。
- `prefers-reduced-motion`：四段動畫全部改為「直接呈現終局」（賽跑直接出時間、輪子直接畫完、珠子直接放在最低點），並以 `matchMedia` 的 `change` 事件即時反應。

## 無障礙

- 全程鍵盤可操作：押注是 `<button>`＋`aria-pressed`；繪圖有等效的滑桿（`<input type=range>`，方向鍵可調）；每幕解鎖後自動把焦點移到下一個可操作元件。
- 計時看板與判詞區為 `aria-live="polite"`，動畫結果會被朗讀。
- canvas 皆有 `aria-label` 描述其內容與替代操作方式。
- 焦點樣式為黃銅色外框，對比明顯。
