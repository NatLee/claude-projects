# 我們留了一盞小燈

**2026-08-20｜網路趣聞・冷知識｜📷**

**敘事容器**：before／after 的親身對照 ＋ 一台會跟著你捲到最後的假監視器（第一屏白爬樓梯 → 走廊上那台機器 → 三步組裝 → XCoffee 釘在畫面角落 → 接上全世界 → 09:54 關機 → 後來）
**互動形式**：親手下樓三趟、每一趟都白跑 → 三步把攝影機、地板下的線、伺服器接起來 → **打開 XCoffee，一個 128×128 灰階小視窗從此釘在螢幕角落；「下樓倒一杯」那顆按鈕會在壺空的時候自己變灰** → 按下開關讓訪客數滾到兩百萬 → **按住 1.5 秒，親手關掉世界上第一台網路攝影機（不可逆）**

## 這一頁的故事線

**鉤子**──不從「世界上第一台網路攝影機」開始，而從一個很小的、每個人都懂的難堪開始。近全黑的第一屏只有兩行字：**你在四樓。咖啡機在三樓的走廊上。** 底下一顆按鈕：下樓看看。不解釋任何名詞，不提劍橋、不提網路，先讓讀者自己走那三層樓梯。

**鋪陳（讀者先受苦）**──按下去，進度條從 4F 走到 3F，走廊的燈亮起來，壺是空的。第二趟：還是空的，走廊上一個人也沒有，你連可以怪的人都沒有。第三趟之後按鈕自己失效，換上一行字：「你不想再爬了。」計數器停在 **白爬的樓梯：3 趟**。這三趟是全頁的地基——後面所有事情的價值，都是用這三趟換算的。接著才交代這是 1991 年冬天的劍橋大學電腦實驗室：十五個人、一台濾泡式咖啡機，而且機器擺在特羅伊房間門外的走廊上。

**轉折**──他們沒有開會，也沒有寫提案。三顆按鈕、一天的工：把攝影機綁上實驗室鐵架、把線從地板下穿過去、一個人寫伺服器一個人寫客戶端。裝置圖一件一件亮起來，最後跳出一個 128×128 的灰階小視窗。

**高潮（由讀者親手觸發）**──「打開 XCoffee」。按下去之後，那個小視窗**釘在畫面右下角，一路跟著讀者捲到頁尾**，每分鐘更新三次（模擬真實速率），壺會被煮滿、被一杯一杯倒空、再被重新煮滿。旁邊的「下樓倒一杯」按鈕會**隨著畫面上的液面自動啟用或變灰**——壺空的時候，它自己告訴你不要去。白爬的樓梯計數器從此停在 3，再也不動。這是全頁真正的「哇」：發明的價值不是用讀的，是那顆自己變灰的按鈕撞出來的。

**擴大**──1993 年瀏覽器學會顯示圖片，Daniel Gordon 和 Martyn Johnson 把它接上全球資訊網。讀者按下「接上網」，散在畫面上的光點一顆顆亮起，計數器滾到一百萬——1996 年，有記者算過，來看這台咖啡壺的人比國王學院禮拜堂的訪客還多，它因此是東英格蘭第一名的觀光景點——再滾到兩百萬。然後攤開那個網頁上真正寫過的兩句服務說明，其中一句是本頁標題的來源。

**記憶點**──2001 年 8 月 22 日上午十點五十四分。讀者必須**按住 1.5 秒**才關得掉，按鈕上的進度條給了猶豫的空間；放開就重來。按滿之後畫面收成一條線、一點白，然後全黑，小視窗從此消失，再按只會得到「已經關掉了」。結尾把鏡頭拉遠：世界上第一台網路攝影機，發明的理由是不想白爬三層樓梯；它拍的東西一天裡大部分時間什麼都不會發生；那台壺後來被 Krups 的員工義務修好，在《明鏡》編輯部又煮了幾年咖啡，現在長期借展在德國帕德博恩的博物館。最後兩行回扣那盞小燈：**壺還在。只是那盞小燈，沒有再為誰開著了。**

## 這是什麼

一頁講「特羅伊房間咖啡壺」（Trojan Room coffee pot）的互動敘事——世界上第一台網路攝影機。它 1991 年誕生於劍橋大學電腦實驗室，1993 年 11 月接上全球資訊網，2001 年 8 月 22 日關閉。

## 怎麼玩

1. **下樓看看**：按三次，體驗 1991 年沒有攝影機時的日常。三趟之後按鈕會自己失效。
2. **三步組裝**：依序按 ①②③，看那套裝置怎麼在一天之內接起來。
3. **打開 XCoffee**：小視窗會釘在畫面角落（手機在底部）跟著你到最後。
   - 「下樓倒一杯」只有在畫面上看得到咖啡時才按得下去。
   - 「快轉一小時」可以看完一輪煮滿 → 被喝光 → 重煮的循環。
4. **接上網**：看訪客數從 0 滾到兩百萬。
5. **按住 1.5 秒關掉它**：不可逆。放開就重來，按滿就結束。

## 為什麼有趣

因為這是一個「動機小到不好意思講、影響大到寫進歷史」的發明。它不是為了發明網路攝影機而做的，是為了不要白爬三層樓梯。頁面刻意把順序倒過來：先讓讀者白爬三趟，再把發明交到他手上——這樣那顆會自己變灰的按鈕才有重量。

另外一個少被提到的細節：那個服務說明頁上寫著「特羅伊房間的燈不是一直開著，但我們會留一盞小燈照著咖啡壺，讓你晚上也看得到。」有人為了地球另一端的陌生人，特地在半夜留了一盞燈。這句話成了本頁的標題與結尾。

## 方法論與取捨

- **時間**：頁面上寫「上午十點五十四分」（劍橋當地時間）與「09:54 UTC」，兩者是同一刻，夏令時間差一小時。兩個來源分別記錄這兩種寫法，因此並列而不擇一。
- **咖啡壺模擬**：`stepSim()` 是一個三態機（`empty → brewing → full → empty`）。煮滿一壺設為 6 分鐘、一杯約八分之一壺、倒咖啡的間隔在 45–260 模擬秒之間隨機。真實 1 秒 = 模擬 30 秒；畫面每 20 模擬秒才更新一幀，換算就是原始系統的「每分鐘三次」——那種一格一格跳的頓挫感是刻意保留的。
- **畫面**：整張圖是 canvas 畫的（先在 128×128 的離屏 canvas 上畫完，加掃描線與顆粒，再用 `imageSmoothingEnabled = false` 放大貼上），不是照片。第一屏走廊那台是同一個繪圖函式的彩色版。
- **訪客光點**：抽象示意，不是真實地理分布；只有 1996 年破百萬、1998 年破兩百萬這兩個數字是有出處的。
- **未採用**：曾考慮把「XSandwichVan」「XPrinterOutputTray」這兩個被提過但沒做成的後續點子寫進去，最後拿掉——它們很好笑，但會稀釋結尾的重量。

## 測試

- `node tools/check.js` 全過。
- 另以 node 斷言驗證抽出的純函式：`clockOf()` 的時間換算（含跨日）、`stepSim()` 的狀態轉移（`empty` 必須等到 `brewAt` 才開煮、煮滿的瞬間 `level` 正好是 1、喝到零會轉回 `empty`）、12 小時長跑的不變量（`level ∈ [0,1]`、狀態合法、事件佇列上限 24、三種狀態都出現過）、以及快轉的可重現性。
- 另以 jsdom 實際載入頁面跑完整條動線（三趟樓梯 → 組裝 → 開啟 XCoffee → 倒一杯 → 快轉 → 接上網 → 按住關機 → 視窗收起），確認全程無執行期錯誤；並在 `prefers-reduced-motion: reduce` 模擬下重跑一次，確認每一段都有降級路徑且結果一致。

## 渲染地雷檢查

- 全頁沒有 SVG，因此沒有漸層描邊與零面積路徑陰影的問題。
- canvas 一律有 CSS 尺寸；`fitCanvas()` 在回寫 `width/height` 前先比較新舊尺寸是否相同，避免 dpr 迴圈翻倍。
- 沒有使用 `stroke-dasharray` 畫線動畫；進度條與連接線都改用 `transform: scaleX/scaleY`，並在重播前先 `remove` class、讀 `getBoundingClientRect()` 強制 reflow，再重新加上。
- 動畫只用 `transform` 與 `opacity`；主迴圈用 `requestAnimationFrame`，`document.hidden` 時暫停累積；`prefers-reduced-motion` 有 `matchMedia` 的 `change` 監聽，切換即時生效。

## localStorage

前綴 `tjcoffee.`，只寫一個 key：`tjcoffee.state`，存 `{ trips, cups, off }`。唯一的用途是在你之前已經關掉過攝影機時，把第五章的提示換成一句「你上次已經把它關掉過一次了，這次可以再看它久一點」。清掉不影響任何功能。
