# 🍵 我是一個茶壺（2026-08-28）

## 故事線

1998 年 4 月 1 日，一份格式無懈可擊的標準文件送進了 IETF——RFC 2324「超文字咖啡壺控制協定（HTCPCP/1.0）」，作者 Larry Masinter。審稿人挑不出任何毛病，唯一的問題是：它是寫給咖啡壺用的。頁面把你放進一台假終端機，讓你親手玩這個協定：`BREW coffee://pot-1` 煮出一杯 200 OK，`Accept-Additions: milk` 加奶，點「珍珠」會被壺用 406 拒絕。接著終端機掃到另一台裝置 teapot-1——你對茶壺發出 BREW coffee，螢幕「噹」一聲吐出 **418 I'm a teapot**，ASCII 茶壺亮起，整頁變成茶壺主題。然後快轉到 2017 年：IETF HTTP 工作小組主席開 issue 要 Node、Go、ASP.NET 移除這個「非正式」狀態碼，15 歲的 Shane Brunswick 連夜架了 save418.com，你按下「#save418」加入連署，看提案一個個收回、418 被正式保留、RFC 9110 落款「418 (Unused)」。回馬槍：往後你在哪個網站撞見 418，那不是錯誤，是暗號——這裡有人記得 1998 年的那個愚人節。

## 這是什麼

「每日小專案」的一頁純靜態互動敘事：用假終端機重演 HTCPCP 協定與 418 狀態碼從愚人節玩笑、被判死刑、到被全網救回的完整歷史。單一 HTML 檔，無外部資源；頁內所有「HTTP 對話」都是本地模擬，不發出任何真實請求。

## 怎麼玩

1. 打開 `index.html`（file:// 雙擊即可），看完開場後點快速鍵或直接輸入指令。
2. 試試：`BREW coffee://pot-1`（煮咖啡）、`; Accept-Additions: milk`（加料）、`WHEN`（停止加奶）、`GET` / `PROPFIND`（查壺況）、`HELP`。
3. 出現 teapot-1 之後，對它發 `BREW coffee://teapot-1`——這就是高潮。
4. 往下捲進 2017 年，按「加入 #save418 連署」看結局。
5. 鍵盤：`Enter` 送出、`Esc` 跳過逐字輸出；全程可用鍵盤操作。彩蛋：`koffie://`、`kaffee://` 等多國語言 scheme 也通（真的在 RFC 裡）。

## 為什麼有趣

- 418 是唯一一個「為了說我不要」而生的狀態碼，而且是玩笑出身、19 年後差點被刪、最後被一場網路運動救回並寫進正式標準（RFC 9110 的「418 (Unused)」）的奇特存在。
- RFC 2324 本身是高級諷刺：Masinter 用一份格式完美的假標準，嘲諷 1998 年「什麼都往 HTTP 上接」的風氣——結果諷刺本身也被大家認真實作了。
- 指令解析器抽成純函式（`parseRequest` / `respond`，位於 `__PURE_START__` 標記區塊），遵守 RFC 2324 核心規則（coffee: scheme、BREW/WHEN、Accept-Additions→406、teapot→418），可直接用 node 跑斷言驗證。
