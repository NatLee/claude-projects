# 史上最貴的一橫 ☄️（2026-08-31・奇聞軼事）

## 故事線

1962 年 7 月 22 日，發射控制室。第一屏就是倒數與控制台燈號：距離自毀按鈕被按下，還有 293 秒。接著時間倒回十二小時前——你是導引軟體工程師，面前是手寫的導引方程規格與謄寫後的程式，你負責「簽核放行」。規格上 Ṙₙ 頭頂那條上橫線印得極淡，第一次幾乎必然看不出來（這是設計好的陷阱）。點火：升空正常 → 雷達測速訊號失聯 → 未平滑的雜訊被導引當成真實速度，過度修正讓軌跡開始蛇行 → T+293 越過毀壞界線，白屏一拍，自毀。調查章把規格放大、缺橫線的那一格反白，你才看見自己放行了什麼。高潮：你親手在 Ṙ 頭頂拖一筆、把 overbar 畫回去，重新發射——同樣的雜訊出現，這次平滑函式接住了，軌跡穩穩往金星去。之後開庭審三個流傳版本（連字號說／上橫線說／FORTRAN 逗號說），順手教會讀者「指數移動平均」，還附一支 α 滑桿讓你把平滑拉到失效、看火箭再蛇行一次。回馬槍：36 天後，水手二號帶著同一份改好的程式成為史上第一個成功的行星際任務——那條橫線如今橫在人類與行星之間。

## 這是什麼

單檔互動敘事頁：把水手一號（Mariner 1）自毀事故做成「發射控制室」體驗，含簽核陷阱、失敗發射模擬、親手補上 overbar 的重飛模擬、三個訛傳版本的考證，以及平滑（移動平均）概念的小教學。純靜態、單一 HTML，`file://` 雙擊即可開啟，無任何外部資源。

## 怎麼玩

1. 第一章按「簽核放行」（放心，你看不出問題的）。
2. 第二章按「點火」，看雜訊如何被當成真值、軌跡如何蛇行到 T+293 自毀。灰線＝原始雷達值、琥珀線＝導引相信的值、主線＝航道側偏。
3. 第三章看調查委員會把缺橫線那格放大反白。
4. 第四章在 R 頭頂的虛線框裡「橫向拖一筆」補上 overbar（也可按「用鍵盤補上橫線」），然後「重新發射」。成功後出現 α 滑桿：拉到約 0.6 以上，平滑失效、火箭又蛇行——平滑不是裝飾，是保險絲。
5. 第五章逛流言法庭，尾聲看水手二號的回馬槍。

## 為什麼有趣

- 「簽核陷阱」讓讀者親身重演 1962 年那位檢查者的處境：極淡的一條橫線，事前根本看不見，事後無比刺眼。
- 失敗與成功用同一顆亂數種子、同一串雜訊、同一套控制律，唯一變因就是那條橫線（平滑函式有沒有接進回路）——「一橫之差、兩種宇宙」不是修辭，是可重播的模擬。
- 考證本身就是劇情：連字號、上橫線、FORTRAN 逗號三個版本並排開庭，順便示範「傳說偏愛漂亮句子」的傳播學。

## 資料來源與考證細節

### 基本事實（有共識）

- 1962-07-22 世界時 09:21 左右，Atlas-Agena B 搭載 Mariner 1（美國第一個行星探測器，目標金星）自卡納維爾角發射；升空約 293 秒後因偏航危及航道與人口區，靶場安全官（Range Safety Officer）下達毀壞指令；再晚約 6 秒火箭即脫離地面控制範圍。損失通常記為約 1,850 萬美元（1962 年幣值）。來源：NASA NSSDCA Mariner 1 條目、JPL 任務紀錄、NASA 歷史辦公室（history.nasa.gov）相關文章。
- 1962-08-27 Mariner 2 發射（相隔 36 天），1962-12-14 以約 34,773 公里距離飛掠金星，為史上第一個成功的行星際任務。來源：NASA/JPL Mariner 2 任務紀錄。

### overbar 與 hyphen 的說法差異（本頁核心考證）

- **官方版（overbar，上橫線）**：事故調查指出，地面導引程式在「雷達測速訊號品質不良／短暫失聯」期間，本應使用**平滑後**（smoothed／averaged）的徑向速度 Ṙₙ。手寫規格中 Ṙₙ 頭上應有一條 overbar 表示平滑值；謄寫進程式時漏掉了。於是未平滑的雜訊被當成真實速度擺動，控制系統不斷修正不存在的偏差，導致實際偏航。此為 NASA 官方紀錄與 NASA 歷史辦公室後世考證的一致說法（亦見 NSSDCA 條目的 "missing overbar/hyphen" 討論）。
- **流行版（hyphen，連字號）**：當年媒體（含《紐約時報》）將缺失字符描述為 hyphen；Arthur C. Clarke 在《The Promise of Space》（1968）中稱之為「史上最貴的連字號」（"the most expensive hyphen in history"），此語廣為流傳。嚴格說 hyphen 是「字與字之間」的一橫，overbar 是「符號頭上」的一橫，媒體用字並不準確；不過部分官方文件早年也曾混用 "hyphen" 一詞來俗稱該符號，這是兩說糾纏至今的原因之一。
- **都市傳說版（FORTRAN 逗號）**：「`DO 5 K=1,3` 打成 `DO 5 K=1. 3`，被編譯器解讀為變數賦值 `DO5K=1.3`」的故事確有其事，但那是**水星計畫**（Project Mercury）地面軌道程式的往事——在測試中被發現並修正，未造成任何飛行事故，與 Mariner 1 無關。1976 年 G. J. Myers《Software Reliability: Principles and Practices》一書誤將其與 Mariner 1 連結，此後兩事常被混為一談（此考證見約克大學 S. Stepney 整理的 "Fortran bug Urban Legend"、RIT 物理課程資料 fortran.txt、alt.folklore.science 早年討論串等）。

查證時參考（2026-09-01 檢索）：NASA 歷史辦公室與 NSSDCA 之 Mariner 1 紀錄轉述（scienceblog.com、spacedaily.com、maketecheasier.com 之近期整理文章）、www-users.york.ac.uk/~ss44/cyc/p/fbug.htm、spiff.rit.edu/classes/phys317/lectures/boom/fortran.txt、sarahandrobin.com/ingo/swr/mariner1.html。頁內事實敘述以 overbar 說為準，hyphen 與 FORTRAN 逗號兩說明確標示為訛傳／另案。

### 誠實聲明（模擬的簡化）

頁內的「控制回饋模擬」是教學用玩具模型（一階航向＋一步延遲＋比例修正＋指數移動平均），並非 Atlas 實際導引律；「雷達失聯發生時點」在真實事故中亦非單一瞬間。模型只為呈現機制：同一串雜訊，未平滑則回路發散、有平滑則收斂。時間軸依模擬越界步數線性映射到 T+293，屬敘事壓縮。

## 核心純函式（可 node 斷言）

`index.html` 內 `<script>` 開頭的 `makeRng` / `expSmooth` / `smoothSeries` / `simulateFlight` 為無 DOM 依賴的純函式。驗證範例：

```js
// 將 <script> 內純函式區塊存成 pure.js 後:
const {simulateFlight} = require('./pure.js');
const assert = require('assert');
const raw = simulateFlight({smooth:false});
const sm  = simulateFlight({smooth:true, alpha:0.10});
assert.ok(raw.destructAt > raw.onset);   // 無平滑 → 發散、越過毀壞界線(實測 step 230)
assert.ok(sm.destructAt === -1);         // 有平滑 → 收斂(實測 maxDev ≈ 1.19,界線 50)
assert.ok(simulateFlight({smooth:true, alpha:0.8}).destructAt >= 0); // 平滑太弱 → 又發散
```

以上斷言已於 Node v22 實際執行通過；`node --check` 語法檢查亦通過。
