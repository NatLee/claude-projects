# 你看不出來我丟了什麼

## 故事線

- **鉤子**：一個上傳進度條走到 97% 就停住，紅字寫著「上傳失敗：檔案不得超過 2 MB」。你那張照片 4.7 MB。
- **鋪陳**：1986 年成立的那個委員會，想的不是「怎麼記得更精簡」，而是一個近乎作弊的問題——哪些東西可以直接不要，而你不會發現？他們翻的是眼球的規格書。
- **轉折（互動一）**：把示範照片拆成亮度層與顏色層，你親手把其中一層的解析度砍到 1/16。砍顏色，你幾乎看不出來；砍亮度，砍到一半就受不了。你剛剛替他們驗證了那個賭注。
- **高潮（互動二）**：換你上機。拖進自己的照片，拉品質滑桿，看檔案大小往下掉，左右拉分界線找差別——找不到。按下「重新上傳」，第一屏那個紅色的框變成綠色，寄出去了。
- **記憶點（回馬槍）**：按「看看你丟掉了什麼」。原圖減壓縮圖、差值放大，一片近乎全黑的畫面裡浮出邊緣、皺褶、細紋的鬼影。它沒有平均地偷，它專挑你來不及停下來看的地方。而你到現在都還沒想把它要回來。

敘事容器：**假介面（上傳失敗對話框）＋實驗室**——第一屏的那個對話框不是裝飾，它是全頁的計分板，成功壓到上限以下時會被真的「修好」。

## 這是什麼

一頁講 JPEG 為什麼能騙過你的互動敘事，同時是一個真的能用的照片壓縮工具：

1. **亮度／顏色分離實驗**：把 RGB 轉成 YCbCr，對指定的那一層做 f×f 盒狀降取樣再放大，即時重繪。畫面左側刻意放了兩塊測試條——彩色細紋（色度殺手）與黑白細紋（亮度殺手）——讓差異一眼可見。
2. **壓縮實驗室**：拖入任何照片（或用內建的程序生成示範圖），調品質、限制最長邊、選檔案大小上限，即時看壓縮後的位元組數、節省比例與左右對照；「自動壓到剛好」用二分搜尋找出不超過上限的最高品質；可下載壓好的 JPEG。
3. **差值鬼影**：把原圖與壓縮結果逐點相減、放大 2～40 倍，看見編碼器實際丟掉的東西。

## 怎麼玩

- 互動一：切換「顏色／亮度」，拉「解析度砍到」。建議先把顏色拉到 1/16，再切到亮度拉 1/2。
- 互動二：直接拉「品質」；或按「自動壓到剛好」。想要戲劇效果，就丟一張手機拍的原檔進去。
- 讀完再按「看看你丟掉了什麼」，把「放大」拉到 20 以上。

## 為什麼有趣

大部分人知道「JPEG 會失真」，但沒有人看過失真本身長什麼樣子。差值影像把抽象的「品質損失」變成一張具體的、有形狀的圖——而且那張圖的形狀（全是邊緣與紋理）正好就是整套演算法的設計邏輯。故事講的是知覺被利用，證據則由使用者自己的照片提供。

## 資料來源與方法論

- ITU-T Recommendation T.81 / ISO/IEC 10918-1（JPEG 標準，1992-09-18 發布；工作小組 1986 年成立）。
- 色度抽樣：4:2:0 模式下最小編碼單元為 16×16，Cb/Cr 兩個平面橫豎各減半，色彩取樣數降為 1/4。
- 色彩轉換採 JFIF 沿用的 BT.601 係數（Y = 0.299R + 0.587G + 0.114B，Cb/Cr 以 128 為中點）。
- 人眼對亮度空間細節的敏感度高於色度，是色度抽樣的生理依據（視網膜中桿細胞數量遠多於錐細胞，且色度通道的空間對比敏感函數截止頻率較低）。
- 頁面中的「壓縮」由瀏覽器內建的 JPEG 編碼器執行（`canvas.toDataURL('image/jpeg', q)`）。**品質數值不是標準的一部分**：同一個 q 在不同瀏覽器對應的量化表不同，因此檔案大小會因瀏覽器而異。頁面顯示的位元組數由 base64 長度換算，與實際下載檔案一致。
- 互動一的「砍解析度」是盒狀平均降取樣後放大，用來示意色度抽樣的效果，不是 JPEG 編碼器內部的實作。
- 示範圖為頁面即時以 Canvas 2D 程序繪製（含刻意加入的顆粒雜訊，模擬真實照片的高頻成分），無任何外部素材。

## 技術註記

- 純靜態、自包含，`file://` 雙擊可開；不使用 module、不 fetch 本機檔、無任何外部資源。
- 使用者的照片以 `FileReader` 讀成 data URL 後繪入 canvas，不會離開這台電腦；因為是 data URL，canvas 不會被污染，`getImageData` 可正常運作。
- 核心邏輯抽為純函式（`rgb2ycc` / `ycc2rgb` / `subsampleRGBA` / `boxify` / `dataUrlBytes` / `fmtBytes` / `fitSize` / `diffRGBA` / `bestQuality`），已用 node 斷言驗證：YCbCr 來回誤差 < 0.6、factor=1 為恆等、chroma 模式不改變亮度、boxify 均值守恆且非整除尺寸不越界、位元組數對照 `Buffer`、二分搜尋結果「合格且再高一格即超限」。
- canvas 一律以圖片原始尺寸設定 width/height 屬性、CSS 寬度 100%，不做 dpr 回寫，避開 ResizeObserver 每幀翻倍的地雷。
- 滑桿更新以 rAF ＋ 110ms 節流，放開後再補算一次，大圖拖曳不卡。
- `prefers-reduced-motion`：第一屏的上傳動畫直接跳到失敗狀態，捲動改為瞬移。

## localStorage

前綴 `jpegq.`，共四個鍵：`jpegq.q`（品質）、`jpegq.lim`（大小上限）、`jpegq.max`（最長邊）、`jpegq.cut`（比較分界線位置）。
