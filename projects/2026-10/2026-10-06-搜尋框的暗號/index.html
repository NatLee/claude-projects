問題是：你打的字，跟它寫的字不一樣。

這台機器很笨，笨得很誠實

掘字是一台小搜尋引擎，只收了 56 份文件——全是虛構的市政公告、新聞、懶人包、論壇和轉貼站，網域都以 .example 結尾。它聽不懂意思，只認字：你打的每個字，它去每份文件裡找；找得到的留下，找不到的淘汰，再按「字出現在標題還是內文」和「這個網站多熱門」排名。

真實的搜尋引擎聰明得多，會猜同義詞、會改錯字、會讀懂問句。但不管它多聰明，你能控制的，就只有打進框裡的那幾個字。

下面有八張委託單。每張背後都有一份文件，被雜訊埋著。輸入時清單會即時更新，按 Enter 交件；失敗三次，示範寫法會自己浮出來。

      第七張委託單為什麼不一樣

      前六張，你在學篩子：引號篩掉改寫、減號篩掉同名、site: 篩掉轉貼、日期和檔案類型篩掉舊版。到了第七張，篩子全部失靈——市府那份押金爭議須知，通篇沒有「房東」，也沒有「押金」。它寫的是「出租人」「承租人」「押租金」「返還」。

      運算子只能從已經存在的字裡挑。如果你打的字根本不在那一頁上，篩子越細，留下的越少，最後一筆不剩。

      名稱

      關鍵字思維——不要描述你的問題，去猜「那一頁上會寫哪些字」。

      選項

      1. 用作者的詞彙，不用你的問題句。

        寫那份文件的人，用的是他那一行的行話：法律寫「出租人」、醫學寫「腹瀉」、工程師寫錯誤代碼。最快學到行話的地方，常常就是排名第一的那篇雜訊——它為了被搜到，會順手把正式名稱寫出來。

        你想房東不還押金怎麼辦它寫押租金 返還 出租人
      2. 具體名詞勝過形容詞。

        「很好用」「最新」「推薦」是每一頁都會寫的字，等於沒篩。能指認的東西才有用：型號、地名、機關名、標準編號、專案名。

        你想公車 App 的資料去哪裡拿它寫公車動態 介接規格書 API
      3. 錯誤訊息整段照貼，加引號，拿掉只屬於你的部分。

        錯誤訊息不分國界，人人看到的都是同一串字。把路徑、帳號、你的檔名去掉，留下固定的那段，用引號包起來。

        你想python 跑不動 找不到 pandas它寫"ModuleNotFoundError: No module named"
      4. 同一個東西，列出所有叫法。

        自行車、單車、腳踏車；健保、全民健康保險；AI、人工智慧。叫法一列出來，就能用 OR 一次撈齊。

      5. 換一種語言。

        技術和學術題材，英文寫成的頁面常常多得多。中文找不到時，把關鍵名詞換成英文術語再試一次，例如「過擬合」→ overfitting。

      注意

      掘字是教學用的玩具：56 份文件、規則簡化。真實引擎會自動擴充同義詞、改寫你的查詢，同一招在外面效果可能更好，也可能更差——所以每招都值得在真的搜尋框裡驗證一次。

      換你：把一個真的問題打進來

      最近一直查不到的那件事，用平常說話的方式打進來。下面這台拆字機會拿掉問句詞、找出核心名詞、換成文件常用的詞，再給你幾種可以拿去真實搜尋框試的寫法。它是規則式的、詞庫有限，粗糙但誠實。

      "精確詞組"
      整段一字不差。
      site:gov.tw
      只看某網站或網域。
      -詞
      排除含有這個詞的頁面。
      after:2023-01-01 before:2023-12-31
      日期區間，可單用也可合用；也接受 2025/11/01 這種寫法。
      filetype:pdf
      指定檔案類型。

      運算子和詞之間不能有空格：site:nytimes.com 可以，site: nytimes.com 不行。不想記語法，可用「工具 → 進階搜尋」表單。Search Central 的除錯頁另列了只在 Google 圖片有效的 imagesize:、src:。

      坊間流傳、官方說明頁沒列

      可能時靈時不靈、隨時會變。清單據 Ahrefs 整理（2023，2026 更新）與維基百科 Google Search 條目。

      A OR B　A | B
      任一個出現即可（要大寫）。
      ( )
      分組，例如 (單車 OR 自行車) 道路。
      "最大的 * 在世界上"
      引號裡的 * 當佔位萬用字元。
      intitle:　allintitle:
      詞要出現在標題。
      inurl:　allinurl:
      詞要出現在網址。
      intext:
      詞要出現在內文。
      ext:pdf
      filetype: 的別名。
      define:詞
      查定義。
      AROUND(4)
      兩詞相距幾個字內；Ahrefs 列為「不可靠」。
      已退役

      別再用；舊教學還在流傳。

      +詞
      舊的「必含」。據 Ahrefs 引 Search Engine Land，2011 年取消；改用引號。有趣的是 Gmail 說明頁至今仍把 + 列為「完全符合該字」——同一家公司，不同產品，語法不通用。
      ~詞
      舊的「含同義詞」。據同一來源，2013 年取消；現在引擎會自己擴充同義詞。
      cache:
      看 Google 快取頁。Google 於 2024 年 2 月移除快取連結（The Verge 報導、維基百科），此運算子也不再提供；舊頁面改去 Wayback Machine 找。
      link:　info:
      據 Ahrefs 引 Search Engine Land，2017 年取消。

      小插曲：連整理清單的文章也會過時——那份 Ahrefs 清單在本頁查證時仍把 cache: 列為「可用」。查語法，回到官方頁。

      日期篩選的提醒：Ahrefs 指出 before:／after: 不一定準，因為頁面更新也會改變它被認定的日期。掘字第四關的「年度」陷阱，在真實世界只會更亂。

      各平台的小陷阱

      • Gmail：用負面運算子時，整串對話仍可能出現，因為它先找符合的「單封信」。搜完可以直接把條件存成篩選器。
      • GitHub：空白就是 AND；repo: 要寫完整的 owner/name；正規表示式不支援 look-around。
      • PubMed：一加欄位標籤（例如 [tiab]）或萬用字元，就會關掉「自動詞彙對應」（Automatic Term Mapping），不再自動帶入 MeSH 同義詞——精準換來的是漏網。同一欄位查多個詞，要每個詞各自加標籤。

      表內各格依 Gmail 說明〈Refine searches in Gmail〉、GitHub Docs〈Understanding GitHub Code Search syntax〉、PubMed Help 整理。其他平台（如論壇站內搜尋）語法差異更大，請找它們自己的說明頁。

      給工程師：捷徑與命令列 Chrome 網站搜尋、ripgrep

      把常用查詢變成網址列捷徑

      Chrome：設定 → 搜尋引擎 → 管理搜尋引擎和網站搜尋 → 「網站搜尋」旁按「新增」。填三欄：名稱、捷徑、以 %s 代替查詢字詞的網址（介面字樣依版本略有不同）。之後在網址列打捷徑＋空白＋關鍵字即可。

      # 捷徑 pm → PubMed
https://pubmed.ncbi.nlm.nih.gov/?term=%s
# 捷徑 mdn → 把 site: 綁死在網址裡
https://www.google.com/search?q=site:developer.mozilla.org+%s

      同一套思維，搬到自己的硬碟

      搜尋框的暗號在命令列都有對應。以下旗標依 ripgrep 官方 GUIDE：

      # 引號（一字不差，不當正規表示式）→ -F
rg -F 'fn write('
# 不分大小寫 → -i；大寫才區分 → -S（smart case）
rg -i timeout
# 完整的字才算 → -w
rg -w id
# filetype: → -g 'glob'；排除類型 → -g '!glob'
rg 押租金 -g '*.md'
rg lexopt -g '!*.toml'
# site:（限定範圍）→ 直接給目錄
rg 'fn write\(' src
# 前後文 → -C；只算行數 → -c
rg -C 2 'connection refused'
# 搜 PDF → 先轉文字（pdftotext），或用 --pre 前處理器
pdftotext report.pdf - | rg -i 'pm2\.5'

      ripgrep 預設會略過 .gitignore 裡的檔案、隱藏檔與二進位檔——找不到東西時，加 -u（可重複到 -uuu）逐層放寬，或用 --debug 看它略過了什麼。這跟搜尋引擎的「沒收錄」是同一種盲點。

      把查詢當程式碼保存

      好用的查詢字串存進筆記或 repo 的 README，標上日期與用途。下次只改兩個字就能重跑；語法失效時，也知道從哪天開始壞的。

      五題回家作業 去真的搜尋框試

      參考寫法不保證搜到什麼；索引與排名會隨時間變，這正是練習的一部分。

      1. 找一份臺灣政府機關發布的空氣品質年報 PDF。
        空氣品質 年報 site:gov.tw filetype:pdf
        接著加 after:／before: 鎖一年，看筆數怎麼變。
      2. 「It is not the strongest of the species that survives」這句常被掛在達爾文名下，找一個專門追查名言出處的網站怎麼說。
        "not the strongest of the species" site:quoteinvestigator.com
        追溯出處的完整方法，見本系列〈那句達爾文名言是誰寫的〉。
      3. 拿你最近遇到的一則錯誤訊息，去掉自己的路徑與變數，加引號搜。
        "No module named" site:stackoverflow.com
        再拿掉 site: 比一比：官方文件、issue tracker、論壇各占多少。
      4. 用 OR 一次撈三種叫法，再拿掉 OR 只留一種，比較少了什麼。
        (自行車 OR 單車 OR 腳踏車) 道路 規劃 site:gov.tw
        OR 不在官方說明頁上，若行為怪怪的，正好記錄下來。
      5. 挑一個你熟的中文專有名詞，查出它的英文術語，用英文再搜一次，比較頭幾頁的來源類型。
        過擬合 → overfitting regularization filetype:pdf

      延伸練習

      • 挑一個你常去的網站，找出它站內搜尋的說明頁，把它的語法填進上面那張對照表的新一欄。
      • 每週把一次失敗的搜尋記下來：你打了什麼、最後是哪幾個字找到的。一個月後回頭看，會發現自己常漏的是哪一類詞。
      • 同系列其他頁接著談：怎麼判斷找到的來源可不可信、怎麼問 AI 並查核它給的引用、怎麼追到一段引言的原始出處、怎麼把一次搜尋變成反覆覓食的流程。
