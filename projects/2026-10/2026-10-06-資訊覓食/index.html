一次搜尋從來不夠

第三叢越橘上，果子越來越難找了。

狐狸低頭嗅了嗅。剛到的兩分鐘吃到七顆，接下來兩分鐘剩兩顆。下一叢在溪的另一邊，走過去要好一陣子。牠該留下，還是動身？

你盯著搜尋框的時候，站的位置一模一樣。第一頁讀完，第二頁開始重複——要不要換關鍵字、換網站、換個問法？多數人憑感覺決定。這一頁給你一條生態學家算出來的規則，和一套能帶回家的採集流程。

往森林裡走 ↓
第一程　氣味

食物從來不是均勻灑在地上的

1970 年代的生態學家想弄清楚動物怎麼花時間。他們發現食物總是一叢一叢地長——生態學把每一叢叫做「斑塊」（patch）。斑塊之間隔著空地，過去要花時間；斑塊裡的食物越吃越少，每分鐘的收穫一直往下掉。研究這筆帳的學問，叫「最適覓食理論」。

1990 年代，全錄帕羅奧圖研究中心（PARC）的 Peter Pirolli 與 Stuart Card 把這本帳簿搬到人身上。1999 年，他們在《Psychological Review》第 106 卷第 4 期發表〈Information Foraging〉：人找資訊，跟動物找食物用的是同一種算術。一頁搜尋清單、一個網站、一串討論、一個資料夾，都是斑塊。

圖版 I　資訊氣味

動物靠氣味判斷哪邊有吃的；人靠標題、摘要片段、連結文字、網址判斷「點下去有沒有東西」。Pirolli 與 Card 把這些線索叫做資訊氣味（information scent）。氣味越濃越值得過去，氣味變淡就該換方向。同一個問題，三條連結的氣味差很多：虛構示意

  • 「10 個你不知道的充電祕密（第 7 個太驚人）」標題沒有給出任何你要的詞
  • 「討論：充到 80% 就拔有差嗎？（142 則回覆）」有人在問同一題，但得自己翻
  • 「鋰離子電池：循環壽命與日曆老化」出現了專業術語——下一步的關鍵字就在這裡

麻煩的是，你要找的東西會變

1989 年，UCLA 的 Marcia J. Bates 在《Online Review》第 13 卷第 5 期（407–424 頁）指出：傳統資訊檢索的模型假設「一次查詢，換回一批文件」，問題從頭到尾不變。實際上人每讀到一點新東西，問題就被改寫一次；需求不是被最後那一批文件滿足，而是被沿途一顆一顆撿起來的片段滿足。

她替這種找法取了名字：berrypicking，採漿果。漿果散在灌木上，不會一串串掛好等你，得一顆一顆摘，邊摘邊往下一叢走。

兩件事疊在一起：你得決定什麼時候離開這一叢，而你要找的東西會在半路變形。1976 年，一位生態學家替前半件事寫下了一條規則。先別急著看——進森林走一趟。

第二程　森林

九十分鐘，六叢灌木，一個會變形的問題

你有 90 分鐘研究下面這個問題。把狐狸拖進任一叢開始採：每一叢都越採越少；換到下一叢要花路程時間，離得越遠越久；離開的灌木會慢慢再長出漿果。霧裡還藏著兩叢，要先撿到對的線索才看得見。什麼時候離開，全由你決定。地圖、斑塊與數值皆為虛構示意

      規則

      當這一叢的收穫率，掉到整片森林的平均收穫率，就動身。

      “The predator should leave the patch it is presently in when the marginal capture rate in the patch drops to the average capture rate for the habitat.”
      — Eric L. Charnov，〈Optimal foraging, the marginal value theorem〉，Theoretical Population Biology 9(2)，1976

      這條規則叫邊際價值定理（Marginal Value Theorem）。剛才面板上那兩條橫條——紅的「這一叢現在」、綠的「你到目前的平均」——紅條縮到比綠條短的那一刻，就是該走的時候。再待下去，你每多花一分鐘，換到的都比「出去再找一叢」少。

      這條規則有它的邊界。生態學的實驗多半支持它預測的方向（叢越遠、待越久），數字卻常常對不上：動物還要躲天敵、要探索、要應付不確定。人也一樣。規則管得了「何時走」，管不了「問題會變」——後者要靠採漿果的本事：

      第三程　地圖

      把森林畫成你自己的地圖

      規則有了，接下來是能帶走的版本。下面八張圖版照覓食的順序排：先決定要找什麼，再決定去哪找、怎麼記、找誰證實、怎麼讓資訊自己送上門，最後是何時收工。每一張都有入門用法，也有給工程師與研究者的進階層。

      圖版 1　框問題

      出發前先把問題寫下來，寫成能被資料回答的形狀。萬用框架是 5W1H：誰、什麼、何時、何地、為什麼、怎麼做——逐格填，空著的那格通常就是你真正卡住的地方。

      健康與醫學問題用 PICO，實證醫學用來框臨床問題、也用來設計文獻搜尋策略：

      字母意思例：兒童頭痛吃乙醯胺酚有比安慰劑有效嗎？
      P病人、問題或族群頭痛的兒童 → children、headache
      I介入措施乙醯胺酚 → paracetamol
      C比較、對照安慰劑 → placebo
      O想看的結局疼痛 → pain

      四格拆完，關鍵字自己就出來了：children headache paracetamol placebo pain，可以直接丟進 PubMed。也有人加上 T（時間）與 S（研究類型）。

      最後補一行：什麼樣的資料能回答它？「多少、多常」要統計；「合不合法」要法條與判決；「有沒有效」要臨床試驗或系統性回顧；「怎麼設定、為何壞掉」要官方文件、issue 與 changelog；「誰先做出來」要專利或論文。這一行決定你等一下要去哪一叢。

      圖版 2　建詞彙表

      你腦中的說法，常常不是文件裡的說法。開一張表，四欄：日常說法、專業術語、英文（或其他語言）、縮寫或代號。每讀到一篇好東西，就從裡面撿新詞填進去——這張表長大的過程，就是 Bates 說的採漿果。

      日常說法專業術語英文縮寫／代號
      電池變不耐用電池老化、容量衰退battery degradation、capacity fadeSoH（state of health）
      放著不用也會壞日曆老化calendar aging—
      網站突然打不開憑證過期、DNS 解析失敗certificate expired、DNS resolution錯誤代碼原文

      Google Scholar 的官方說明就這樣建議：不熟的領域，先從次級資料學術語——例如讀維基百科的「overweight」條目，可能讓你想到用「pediatric hyperalimentation」去搜。

      圖版 3　選對斑塊：資料庫地圖

      不同的問題長在不同的森林。下面是一張分層地圖：先從一般起點撒網，再依「什麼樣的資料能回答它」走進專門的斑塊。網址與功能查證於 2026-10-06；平台會改版，以官方說明為準

      • 搜尋引擎

        先用日常說法撒網，看前幾筆用什麼詞描述你的問題——那些詞就是氣味，抄進詞彙表。

        精確詞組、site:、日期區間、filetype: 等運算子能大幅縮小範圍；語法細節見同系列的〈搜尋框的暗號〉。

      • 維基百科zh.wikipedia.org

        當地圖用，別當終點。最有價值的是條目底部的參考文獻與外部連結：從那裡往回跳，就是「向後追」。

        切換到英文或其他語言版本，引用的文獻常常完全不同；「討論」與「檢視歷史」看得出哪些段落有爭議。

      • Google Scholarscholar.google.com

        跨領域的學術搜尋。每筆底下的「Cited by」（被引用）看誰引用了它，「Related articles」找相似的，「All versions」找可讀的全文版本。

        author:"d knuth" 依作者找；標題加引號找特定論文；搜尋頁的信封圖示可設快訊。單一查詢最多只顯示 1,000 筆，要更多就把查詢切細。

      • PubMedpubmed.ncbi.nlm.nih.gov

        美國國家醫學圖書館的生醫與生命科學文獻庫，超過 4,000 萬筆書目與摘要。本身不收全文，但常連到出版社或 PubMed Central 的全文。

        MEDLINE 收錄的文章標有 MeSH 主題詞，能把一堆同義詞收成一個標準詞；用 Advanced 頁面組合欄位查詢。

      • arXivarxiv.org

        物理、數學、資訊科學、計量生物、計量金融、統計、電機與系統科學、經濟八大領域的預印本。有版主分類審核，但 arXiv 本身不做同儕審查，引用前要留意。

        提供 API，適合寫程式追蹤某個分類的新論文。

      • SSRNssrn.com

        社會科學起家的預印本與研究論文平台，現收 65 個以上學科。經濟、法律、管理的工作論文常先出現在這裡。

      • DOAJdoaj.org

        開放取用期刊目錄：收錄經同儕審查的開放取用期刊，可以搜期刊也可以搜文章，全文免費可讀。

        提供 API、OAI-PMH 與公開資料傾印。

      • Semantic Scholarsemanticscholar.org

        Ai2（艾倫人工智慧研究所）的免費學術搜尋，索引超過 2 億篇論文，引用與被引用列表整理得很清楚。

        Semantic Scholar Academic Graph（S2AG）提供資料集與 API，適合批次做引用網路分析。

      • 臺灣博碩士論文知識加值系統ndltd.ncl.edu.tw

        國家圖書館的臺灣學位論文資料庫。碩博士論文通常有很長的文獻回顧，是找某個臺灣議題的絕佳起點——直接從它的參考文獻往回跳。

      • 政府資料開放平臺data.gov.tw

        各機關以開放格式釋出的資料集：交通、環境、選舉、實價登錄、食品藥品許可證……

        平臺訂有共通性應用程式介面指引（RESTful 風格），資料集附詮釋資料，適合程式化抓取與定期更新。

      • 中華民國統計資訊網stat.gov.tw

        行政院主計總處的官方統計：物價指數、就業失業、薪資、家庭收支、人口及住宅普查。

        有「預告統計資料發布時間表」可以預先知道數字哪天出來；也提供 RSS。

      • 立法院法律系統lis.ly.gov.tw

        法律全文，加上民國 59 年迄今的立法沿革、立法理由與立法紀錄。想知道「這條為什麼這樣寫」，來這裡。

      • 全國法規資料庫law.moj.gov.tw

        法務部維護的現行法規條文。查「現在的規定是什麼」先來這裡，再去立法院系統查它怎麼來的。

      • 司法院裁判書查詢judgment.judicial.gov.tw

        各級法院裁判書全文。輸入「105訴123」這類簡寫就能查案號；輸入「民訴法226」能找到引用該條文的裁判。

        另有司法院資料開放平臺，適合批次分析。

      • Google Patentspatents.google.com

        搜尋並閱讀世界各國的專利全文，也能找非專利文獻做先前技術比對。

        專利文件列出的引用文獻＝向後追；「被誰引用」＝向前追。追一條技術線，比關鍵字更準。

      • 經濟部智慧財產局：專利檢索tipo.gov.tw

        臺灣專利的官方來源。局網「專利檢索」頁可進入「全球專利檢索系統」與「中華民國專利資料檢索系統」。

        先用國際專利分類（IPC）定位技術領域，再在分類內下關鍵字，能避開同詞異義。

      • 官方文件先行

        先讀你用的那個版本的文件。版本號是工程世界最濃的氣味：同一個錯誤，在不同版本可能是完全不同的事。

      • RFC Editorrfc-editor.org

        RFC 的官方家：網路協定與網際網路標準的原文。

        看 Errata（勘誤）頁；首頁可訂閱新發布的 RFC。

      • MDN Web Docsdeveloper.mozilla.org

        HTML、CSS、JavaScript 與 Web API 的參考文件。

        參考頁附規格表與瀏覽器相容性表：先確定功能在哪份規格、哪些瀏覽器支援，再決定要不要用。

      • GitHub Issues 與 Discussions

        把錯誤訊息原文加引號搜 issue，包含已關閉的——你遇到的問題，常常早就有人回報、有人修好。Discussions 的問答分類可以把留言標成解答。

        要搜程式碼本身，用 GitHub Code Search（語法見〈搜尋框的暗號〉）。

      • Stack Overflowstackoverflow.com

        程式問答網站。讀回覆時注意年份與版本：十年前的高票解法，未必適用你手上的版本。

      • CVE.org 與 NVDcve.orgnvd.nist.gov

        公開漏洞的編號與細節。CVE 編號是完美的精確關鍵字：拿它去串起公告、修補、討論與 exploit 分析。

      • 套件 registry 與 Releasesnpmjs.compypi.org

        套件頁、CHANGELOG 與 GitHub Releases 告訴你「版本之間改了什麼」，破壞性變更通常寫在這裡。

      工程師的覓食順序（範例）
      1. 錯誤訊息原文加引號搜一次，記下版本號。
      2. 去該專案的 issue tracker 搜同樣字串，打開「已關閉」。
      3. 對照 CHANGELOG／Releases：問題是哪一版出現、哪一版修好？
      4. 還不清楚就讀原始碼（Code Search），或回到規格（RFC、MDN 的規格表）。
      5. 把查詢、版本與結論寫進搜尋日誌，連同 commit 一起留在 repo。
      圖版 4　搜尋日誌

      覓食最常見的浪費，是忘了自己去過哪一叢。每次查詢記一行：在哪查、用什麼字串、撿到什麼、新詞是什麼、下一步去哪。兩週後回頭看，你會發現問題被改寫了好幾次——日誌就是你的路線圖。

      圖版 5　向後追、向前追：Bates 的六招

      Bates 在 1989 年那篇論文裡整理了研究者實際在用的六種採集法。三十多年後，每一招都還在，換了工具而已：

      Bates 的說法做法現在用什麼
      Footnote chasing（向後追）從一篇好文章的參考文獻往回跳論文參考文獻、維基條目的註腳、專利的引用文獻
      Citation searching（向前追）找出誰引用了它，往後跳Google Scholar 的 Cited by、Semantic Scholar 的引用列表
      Journal run鎖定一本核心期刊，一期一期翻核心期刊目錄、核心 repo 的 Releases、某機關的發布時間表
      Area scanning在找到的東西旁邊逛「相關文章」、同分類、同 topic、同書架
      Subject searches用索引與主題詞查PubMed 的 MeSH、專利的 IPC 分類、資料庫主題分類
      Author searching找到好作者，看他還寫了什麼author: 運算子、Scholar 作者頁
      圖版 6　三角驗證

      重要的說法，至少找兩到三個彼此獨立的來源。「獨立」的意思是它們沒有互相轉述、沒有共用同一份新聞稿、背後不是同一個人。十篇文章引用同一份報告，只算一個來源。

      最好的組合是不同種類的斑塊互相印證：一份官方統計＋一篇同儕審查論文＋一位直接經手的人的紀錄。判斷來源可不可信，見同系列的〈查核員先關掉了那個分頁〉；順著引用往回追到最早的出處，見〈那句達爾文名言是誰寫的〉。

      圖版 7　讓資訊自己來

      好的覓食者記得哪幾叢會再長出漿果。設好訂閱，新東西長出來時，它會自己通知你：

      • Google 快訊（google.com/alerts）：對關鍵字設快訊，頻率可選即時、每天最多一次、每週最多一次，來源可選新聞、部落格、網頁等。
      • Google Scholar 快訊：在搜尋頁按信封圖示；也能對某篇論文的「Cited by」設快訊，有新論文引用它就通知你；或在作者頁按「Follow」。
      • RSS：很多官方網站還提供，例如中華民國統計資訊網。用一個閱讀器把各叢集中起來。
      • GitHub Watch：在 repo 右上角 Watch → Custom，只勾 Releases，就只收新版本通知，不被其他動態淹沒。
      • RFC Editor：首頁可訂閱新發布的 RFC。
      圖版 8　何時收工

      當新來源不再帶來新詞、新證據、新反例——研究方法上叫做資訊飽和——你在這一叢的收穫率已經掉到整趟平均以下。這時候有三條路：換一種斑塊、把問題改寫成下一版，或者收工。

      給自己一個時間盒（例如 25 分鐘），盒子結束時問一句：最後十分鐘撿到幾顆？如果是零，就該動身了。這就是邊際價值定理的口袋版。

      組一套你的採集流程

      把左邊的步驟卡拖進右邊「我的流程」，上下拖動排序；也可以用每張卡上的按鈕加入、上移、下移、移除（手機上請按住卡片左側的 ⋮⋮ 拖曳）。排好的流程會存在這台裝置上，可以複製成 Markdown 或直接列印成一張卡。

            練習：五份自學作業

            作業 1　把一個真問題改寫三次

            挑一個你最近真的想知道的事，用 5W1H 或 PICO 改寫三次，每次更窄、更能被某一種資料回答。寫下每一版「什麼樣的資料能回答它」。

            作業 2　寫一頁搜尋日誌

            用上面的模板，針對作業 1 的問題至少查 8 次、橫跨 3 種以上的斑塊。每次記下撿到的新詞，最後數一數：問題改版了幾次？

            作業 3　向後追三篇、向前追三篇

            找一篇你覺得好的文章或論文。從它的參考文獻挑 3 篇（向後），再用 Google Scholar 的 Cited by 挑 3 篇引用它的（向前）。把這 7 篇的關係畫成一張小圖：誰引用誰、誰反駁誰。

            作業 4　三個獨立來源

            替一個你常聽到的說法找三個彼此獨立的來源（支持或推翻都算）。寫下你判斷它們「獨立」的理由：作者、資金、資料來源是不是不同？

            作業 5　設一叢會自己長漿果的灌木

            為作業 1 的主題設一個 Google 快訊或 Scholar 快訊（工程師：Watch 一個 repo 的 Releases）。兩週後回來數：它帶來幾顆新漿果？依邊際價值定理決定要不要保留這個訂閱。

            終點

            留在灌木上的果子

            狐狸離開第三叢時，枝頭還掛著幾顆越橘。牠看見了，也算過了：把最後那幾顆找出來的時間，夠牠在下一叢吃到更多。

            你剛才在森林裡，也留下了一些沒採的果子。那些不叫浪費——那是你拿去換路程的錢。

            厲害的覓食者不會霸著最大的那一叢，牠知道什麼時候該走。厲害的研究者也不靠一次搜到，他知道下一次該搜什麼——而下一次要用的那個詞，多半就藏在這一次撿到的果子裡。
