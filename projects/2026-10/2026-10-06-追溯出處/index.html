調查筆記（走過的卡）
    下面兩個抽屜還鎖著——先在上面找到最早的那張卡。

    轉

    他從來沒說他在引用

    1963-04-12 · San Antonio · 會長演說（刊於同年 6 月學會季刊 p.4）

    According to Darwin’s Origin of Species, it is not the most intellectual of the species that survives; it is not the strongest that survives; but the species that survives is the one that is able best to adapt and adjust to the changing environment in which it finds itself.

    回頭看那張卡。Leon C. Megginson 沒有用引號。他說的是「根據達爾文的《物種起源》」——後面接的，是他自己對那本書的讀法。講題是〈歐洲給美國企業的教訓〉，場合是西南社會科學學會的年會。他下一句就把話題轉到人身上：能存活的文明，是能適應物質、社會、政治、道德與精神環境變化的那一個。

    隔年他在石油業期刊重寫一次，把「根據」挪到句尾，變成「達爾文如是說」。再過四年，有人把它排成題詞、直接掛上達爾文的名字。之後每轉手一次，它就被削短一點、換一個字、加一對引號。

    一段談「適應」的話，自己也在適應。它的生存環境是簡報、海報和轉貼——越短、越順、名字越大，活得越好。

    Quote Investigator 把這種機制寫得很清楚：A 轉述 B 的觀點；日後，那段轉述被直接當成 B 的原話。2009 年，生物學研究生 Nick Matzke 挖出 1963、1964、1982 這幾個關鍵出處，劍橋的 Darwin Correspondence Project 還為此頒獎給他。

    你剛剛走過的路，他們都走過。差別在他們每一步都記下了頁碼。

    突變檯

    一版一刀：看它怎麼長成名言

    八個版本照年代排好。點年份，跟上一版比：哪些字被刪、哪些字長出來、引號和名字是在哪一版出現的。

    被刪的字　新長出來的字　（英文原句；中文為本頁譯文）

    帶走這組抽屜

    同一套動作，追任何東西的來歷

    一段引言、一張圖、一個網頁、一個數字、一篇論文、一行程式碼——查法不同，骨架一樣：

    1. 找指紋。把主張裡最怪、最不像會被改寫的部分挑出來：罕見用字（像 intellectual）、數字、專有名詞、錯字。名字和漂亮的結論最容易被換掉，別拿它們當主要關鍵字。
    2. 從最近的往回走。每找到一層，就問它：「你從哪裡來？」看它的腳註、引用、日期，再往前一層。
    3. 換變體、加日期上限。同義字、詞形變化、較短的片段；把日期上限設在剛找到的那一層之前。搜尋語法細節見系列的〈搜尋框的暗號〉。
    4. 回到原典或原始資料。原文語言、原始版本、原始資料表。翻譯、懶人包、新聞圖表都是轉手。
    5. 寫下鏈條。每一層的年份、出處、頁碼、你在哪個資料庫看到。說得出整條鏈，才算查過；找不到就寫「最早只追到……」。
    引引言與名言精確詞組、變體、書報資料庫、原典
    • 精確詞組＋變體：先用引號搜整句，再準備 3–5 個變體——拿掉名字、換同義字、只取最怪的片段。早期版本常比流行版長、用字不同，精確詞組會精確地漏掉它們。
    • 日期上限：Google 搜尋可用 before:／after:（例如 before:2000-01-01），也可在 Tools 選時間範圍。一般網頁的日期常不準，往前追要換到書與報紙。
    • 書籍全文：Google Books（可設時間範圍）、HathiTrust 全文搜尋（美國政府出版品特別多——1987 年那份聽證紀錄就在這裡）、Internet Archive 的書與期刊。
    • 報紙：圖書館授權的報紙全文庫（多半用借書證登入）；QI 在報紙全文庫找到 1999 年 USA TODAY 那一版。
    • 原典全文：作者全集網站，例如 Darwin Online（darwin-online.org.uk）。先確認原典裡有沒有，再談「出自某書」。
    • 專門查證：Quote Investigator（每條都附頁碼與是否看過掃描）、Wikiquote 人物頁的 Misattributed／Disputed 段落、作者書信計畫（如 Darwin Correspondence Project）。

    判讀：越早的版本通常越長、越彆扭、有上下文；越晚越短、越順、名字越大。沒有頁碼的出處，不算出處。

    圖圖片與影片反向圖片搜尋、最早副本、EXIF 的限制
    • 反向圖片搜尋：Google Lens、TinEye、Bing Visual Search 各有各的索引，多試幾家。追的是「這張圖」的來歷——字句的來歷要回文字資料庫。
    • 找最早的副本：比較各副本的發布時間，往最早的找；留意裁切、翻轉、加字、調色的版本，最早的往往解析度最高、畫面最完整。
    • 影片：截幾張關鍵影格分別反搜；標題和描述常被重寫，畫面不會。
    • EXIF：相機寫進檔案的拍攝時間、機型，有時有 GPS；可用 exiftool 之類工具讀。限制：可以被改寫，社群平台上傳時也常會清掉——它能佐證，不能單獨定案。
    • 看畫面細節：招牌文字、車牌樣式、季節與天氣，跟宣稱的時間地點對得上嗎？
    網網頁消失的頁、被改過的頁
    • Wayback Machine（web.archive.org）：輸入網址看歷年快照，比對兩個日期的版本，找出被悄悄改掉的段落。看到重要頁面，可以先用 Save Page Now 存一份。
    • archive.today（archive.ph）：另一個存檔服務，常用來保存單頁快照；兩邊都查，覆蓋面不同。
    • 網址線索：/2019/03/ 這類日期路徑、遞增的文章編號都透露時間——但那可能是建立日，不是最後修改日。
    數數據與統計別停在新聞圖表
    • 從圖表找出資料來源名稱，回到發布機構（政府統計機關、國際組織資料庫、研究原文的附表）下載原始資料表。
    • 對齊定義：年份、單位、母體、名目或實質、是否季節調整；初值和修正值可能不同。
    • 讀表格註腳與方法說明——很多「驚人數字」的祕密都藏在註腳裡。
    論學術主張從新聞回到論文，再看前後的引用
    • 回到論文：新聞裡的「研究顯示」→ 找作者與標題 → 找 DOI（https://doi.org/ 加上 DOI 可解析到原文頁）→ 讀方法與限制，不只讀摘要。
    • 往前、往後追：往前看參考文獻（它站在誰的肩上）；往後看被引用——Google Scholar 的 Cited by、Semantic Scholar 都能看誰引用了它、怎麼評。Crossref 提供 DOI 中繼資料查詢。
    • 查撤稿與更正：Retraction Watch Database（2023 年 9 月由 Crossref 取得、開放為公共資源，撤稿資料也進了 Crossref API），以及期刊頁上的 Retraction／Correction／Expression of Concern 標記。
    • 注意層級：新聞稿常比論文說得滿；預印本還沒經過同行審查。
    碼給工程師：程式碼、設定、規格git pickaxe、blame、CDX API

    某段字串是哪一次 commit 長出來的？用 pickaxe：

    # 找出「這個字串出現次數有變」的 commit（誕生或被刪的那一刻）
git log -S'MAX_RETRY = 7' --oneline -- src/

# 把 -S 的字串當正規表示式
git log -S'MAX_RETRY\s*=' --pickaxe-regex -p

# 找「diff 有新增或刪除行符合正規表示式」的 commit（會包含搬動，較吵）
git log -G'retry\(.*timeout' -p

# 追某個函式的演化
git log -L :parseConfig:src/config.js
    • -S 看的是「出現次數有沒有變」，所以檔案內搬動不算；-G 看 diff 行，搬動也會算。官方說明在 gitdiffcore 的 pickaxe 段落。
    • git blame 告訴你每一行最後一次被誰改——那常常不是源頭；配 git log --follow 檔名 跨過改名，再用 -S 找誕生點。
    • GitHub 上可以搜 commits，也可以用 code search 的精確字串找「誰複製了這段」（語法見〈搜尋框的暗號〉）。
    • 規格的原典：RFC（rfc-editor.org，記得看 errata）、W3C／WHATWG、ECMA、ISO。部落格與問答網站是二手。

    某個網址有哪些快照？Wayback 的 CDX API：

    https://web.archive.org/cdx/search/cdx?url=example.com/pricing
  &output=json&from=2015&to=2020
  &fl=timestamp,original,statuscode,digest
  &filter=statuscode:200&collapse=digest&limit=50
    • url 是唯一必填；from／to 用 1–14 位數的 yyyyMMddhhmmss；fl 選欄位；filter=欄位:正規表示式（前面加 ! 反選）；collapse=digest 摺疊相鄰的相同內容，等於只看「真的改過」的版本；limit=-1 取最後一筆；matchType=prefix 查整個路徑底下。
    • 拿到 timestamp 與 original 後，https://web.archive.org/web/{timestamp}/{original} 就是那份快照。
    練五個自己去追的題目練到變成反射動作
    1. 挑一段你常在簡報上看到、掛在某位名人名下的名言。拿掉名字、找出它的「怪字」，用書籍資料庫加日期上限，追到你能找到的最早版本；寫下每一層的頁碼。
    2. 找一張社群上流傳、號稱是某個歷史時刻的照片。用兩家反向圖片搜尋找最早的副本，比對各副本的說明文字有沒有變。
    3. 挑一則寫著「研究顯示」的新聞。找到論文 DOI，讀方法段，再查有沒有更正或撤稿，並看三篇引用它的論文怎麼說。
    4. 找一個你常用的官方說明頁或服務條款，用 Wayback Machine 比對它三年前的版本，列出改了什麼。（進階：用 CDX API 加 collapse=digest 列出所有「內容真的變了」的日期。）
    5. 在你自己的專案裡挑一個神秘的設定值或魔術數字，用 git log -S 找出它誕生的 commit，讀當時的訊息和討論，判斷它還該不該在那裡。
    延自學延伸下一步去哪學
    • 把 Quote Investigator 當範本讀：看它怎麼按年代排證據、怎麼標頁碼、怎麼註明「看過掃描」或「看過紙本」——寫你自己的查證筆記時照抄這個格式。
    • 官方文件：git-scm.com 的 gitdiffcore（pickaxe）與 git-log（-L、--follow）；Internet Archive 在 GitHub 上的 wayback-cdx-server README；Google 搜尋說明「Refine Google searches」。
    • 圖書館：大學或公共圖書館的參考諮詢服務、館際合作——很多關鍵出處（像 1964 年那本石油期刊）只在紙本裡。
    • 系列其他頁：判斷來源可信度看〈查核員先關掉了那個分頁〉；請 AI 幫忙找出處、怎麼核對它給的引用，看〈你怎麼問，它就怎麼編〉。
